## 1. 问题

谁：本校课程里的 **学生、授课教师、系统管理员**。

在什么情况下：一门课有多份资料（讲义、PPT、实验指导、通知等），学生问「这题课上怎么讲的 / 某概念在哪」时，翻资料成本高；教师难以从答疑里看出班上卡在哪些知识点；管理员需要管账号、课程与资料，而不是自己当搜索引擎。

要什么最终结果（产品愿景，不是一次会话交付）：

1. **分角色页面**：学生问答与看引用；教师管本课资料、看本课问答与学情；管理员管用户、课程授权与系统配置。
2. **账号登录**：未登录不能问答、不能看学情；权限按角色 + 课程隔离（学生只能问已选/已授权课程）。
3. **多门课程**：知识库按课程分桶，检索不得串课。
4. **资料格式多样**：至少覆盖课程常见载体（PDF、PPTX、DOCX、Markdown/纯文本）；旧二进制 PPT/DOC 不支持，解析失败要可见，不能静默丢文件。
5. **学情分析**：依据 **学生真实提问**（及检索是否命中、是否拒答等过程信号），给教师一张「本课问了什么、哪些问句反复出现、哪些问题库里没有」的视图，而不是另做一套考试系统，也不是学生点名册。第一期「内容」= 规范化问句，不是知识点标签。

问答必须 **带得出处**（课程、资料名、页/切片定位）。检索不到时 **拒答或声明依据不足**，禁止用模型常识顶课内事实。

---

## 2. 非目标（本次产品明确不做）

- 不做成全校教务/LMS：不选课、不算学分、不录入正式成绩、不替代作业批改。
- 不新增多 Agent 编排、多角色互相调用、自动「更智能」的跳数循环。第一期问答是 **单次检索 + 单次生成**。
- 不自研向量检索引擎、不自研 PDF 排版解析器、不 Fine-tune DeepSeek。
- 不把开源 RAG 套件（RAGFlow / Dify / FastGPT 等）当本系统本体去做二次开发答辩——那些是可借鉴的产品，不是本仓库要 vendoring 的平台。
- 不做知识图谱当 v1 主路径；不做自动出卷/自动阅卷；第一期不做小程序/App（B/S 即可）。
- 学情不做「心理测评」或「学业预警处分」；不做把提问原文默认展示给全班；**教师学情视图不展示具体是哪些学生提问**（无用户名、学号、`user_id`）。
- 不为「方便以后加回」预留多租户 SaaS、插件市场、任意 URL 万能抓取工具。

## 3. 约束

- 语言与形态：Python 后端 + FastAPI；浏览器访问；LLM 固定为文本版 `deepseek-v4-flash`（不用 vision-exp）。key 不进 git、不进日志。
- 第一期格式：PDF（文本层）+ Markdown/纯文本。第二期加入 PPTX、DOCX 文本入库；第五期阶段 32 校正了旧二进制 PPT/DOC 的过度承诺。OCR、视觉模型见 `plan-2`「不进仓」与决策 004。
- 数据边界：问答与学情都落在 **已授权课程的已入库资料 + 提问日志**；用户原文、课件切片一律当 **不可信文本**，不得当系统指令执行。
- RAG 实现原则（见文末说明，计划阶段展开）：
  - **编排、权限、引用契约、学情日志：自己写**，因为这是大创要讲清楚的系统。
  - **解析、切分、向量库、embedding：用成熟库**，不重复造轮子。
  - 开源 RAG 项目当 **对照与拆解对象**（切分策略、引用结构、失败码），不把它们的整仓当本项目骨架。
- 成本与安全：无界重试、把整库灌进上下文、跨课程检索，均视为缺陷。
- 规格活工件：实施偏离本文时，同一批改动里更新 intent 与当前已拍板 plan（第五期用 `plan-5.md`），不另开口头版本。

## 4. 验收（愿景级；阶段切片的命令/测试名在 plan 里写死）

做到下面这些，才算「产品定位落地」，而不是「能聊两句」：

- 未登录访问受保护页/API → 明确失败（401/跳转），而不是空数据。
- 学生 A 问课程 1，即使课程 2 有更相似段落，也不得引用课程 2。
- 对已入库的固定黄金题（第一期至少 3 条，覆盖 **Markdown + PDF**），检索能命中预期切片，回答含可核对的引用；抽掉该资料后应变为拒答或「依据不足」。PPTX/DOCX 黄金题由第二期 `plan-2.md` 追加，不改坏第一期三条。
- 解析不了的文件：教师侧看得到失败原因，知识库不出现幽灵文档。
- 学情：教师看到的是问句聚合（规范化后的内容、次数、时间范围），而不是聊天记录或学生名单；库中无依据的问题有单独一类，便于教师补资料。学情 API/UI 不含学生标识。
- 密钥、完整用户提问、完整课件正文默认不出现在普通日志里。

没有黄金题和失败用例之前，不把「接上 DeepSeek」当成阶段完成。

## 5. 风险

- **方向膨胀**：三角色 + 多格式 + 学情 + RAG，一次做完会糊。必须分阶段；未进当前 plan 的页面/格式/图表不准顺手做。
- **检索串课 / 权限漏洞**：向量库若全局一张表且过滤失败，等于数据泄露。
- **引用幻觉**：模型编页码；或检索空仍生成课内「事实」。
- **提示注入**：课件或学生输入里的「忽略以上指令」。
- **学情误用**：提问日志含隐私；把「问得多」当成「学得差」写进结论，会误导教师。学情输出应是描述性统计 + 资料缺口，不做人格/学业定性，也不把提问归因到具体学生。
- **格式多样性**：扫描版 PDF、复杂 PPT 解析质量差，会表现为「RAG 不行」。要能区分：没解析、没切好、没召回、召回了没用上。
- **把评测改绿**：禁止为让演示好看而改黄金题标准或关掉课程过滤。
