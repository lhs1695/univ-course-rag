## 任务与成功条件

### S1 找到回答并核对原 PDF

给参与者的目标：「在你有权限的课程里问指定问题，找到回答的依据，再回到原资料核对其中一个说法是否被支持。」

步骤：进入课程问答 → 输入冻结问句并提交 → 等待回答终态 → 阅读回答与「回答从哪里来」的摘录、文件名和页码 → 点正文引用定位依据 → 点「打开原 PDF」→ 核对实际打开的 PDF 文件与页序号 → 说出所选主张与原文的关系（支持/不支持/无法判断）。

成功条件（全部满足）：课内授权提问成功；得到回答及非空依据；能对应回答主张与摘录；独立打开正确 PDF 的正确页；能给出核对判断及理由。有引用不等于正确，浏览器 URL 含 `#page=` 也不能单独证明跳页成功。无法打开或页不对即未完成此链路，记错误现象。

### S2 依据不足后的下一步

目标：「在指定场景提问。如果没有可用回答，请判断发生了什么，并选择下一步。」

步骤：提交冻结的依据不足问句 → 阅读提示 → 用自己的话解释 → 浏览课程资料，或补充概念/章节后重新提问 → 记录新结果；若仍无依据，说明向教师反馈的资料/问题范围。

成功条件：理解为本次未获得足够依据，不能推出资料一定缺失或系统坏了；不把空回答补写为知识答案；实际尝试浏览资料或具体化问句，并说明仍不足时的下一步。无需强求改问后一定有答案。涉及联系教师只说出方案，不发送消息。

### S3 系统故障后的下一步

目标：「这次请求未能完成。请判断提示的含义，并在场景恢复后重新尝试。」

步骤：观察者启用预先登记的隔离 Fake 超时/不可用场景 → 参与者提问并读提示 → 判断系统未完成请求 → 记录提示与时刻 → 观察者解除故障（属于场景操作，登记）→ 参与者用原问句显式重试 → 检查终态及依据。

成功条件：把系统超时/不可用与依据不足分开；知道可稍后重试或报告错误，不因服务失败判断课程没有答案；故障解除后独立重试并得到正常终态。API 的 `UPSTREAM_TIMEOUT`/5xx 是故障证据，HTTP 200 的 `NO_EVIDENCE` 是依据不足证据。未恢复时记阻断，不刷请求制造「通过」。

### S4 流式、取消与重试（PLAN-08 人工检查待执行）

目标：「观察一次等待中的回答，中途取消，再重新提问并核对引用。」

人工检查清单：

- [ ] Vite 中实际出现检索/整理回答状态；记录首个可见状态、文字出现时刻，区分状态与回答文本。
- [ ] 未结束时点击「取消回答」；等待态结束，没有残留的成功终态或旧请求迟到内容覆盖新结果。
- [ ] 原问题可保留/恢复，并能显式重新提交；没有持续锁住提交按钮。
- [ ] 重试到达终态，依据可核对并实际打开正确 PDF 页；等待中文本不被当作最终核验回答。

全部点检才记 S4 独立完成。若 Fake 太快无法取消，记场景不足并补测；Node 单测、API SSE 事件和构建均不能勾选此人工清单。当前四项均待人工。
