## 一、已确认的方向与范围

1. **教师侧 Agent：必做主线，按 M1→M2→M3 薄切。** 场景锁死为课内问题调查：M1 合同 + Harness + 任务落库可读，M2 调查报告 API，M3 教师 UI + 最小 lease/取消/恢复；最小物理 TTL 已另切；完整定时 TTL 清理与 Trace UI 不作为报告首交付的前置。
2. **课程业务基础：必做。** 按最小必要范围完善学期、班级、学生名单、个人主页及对应权限；教师与管理员资料协作按普通、清晰、可审计的业务流程实现。
3. **GraphRAG / 知识图谱：结题不做。** 全部主线（Agent M1–M3 + 业务最小集）完成并稳定后，才可考虑演示「锦上添花」；不单独立项开工，不阻塞验收。不上默认 LangGraph/LlamaIndex 编排框架。
4. **保留可信 RAG 主线。** 继续处理 Evidence Trace、误拒答、资料生命周期、权限和引用来源；Agent 不替代底层 RAG 质量诊断。
5. **验收边界已确认。** 用户独立试用已取消，采用脚本化测试与开发者 Vite 观察，并明确标注证据级别；空白机部署与备份恢复暂缓，不能写成已通过。

### PLAN-14：合同与 Harness 基线

分期退出已确认：**M1** 合同+Fake/Replay Harness+任务落库可读，创建后可独立读取、无权者读不到（PLAN-14 + PLAN-15 最小存储/权限及创建/单任务读取 API）；**M2** 调查报告 API（PLAN-16），schema/来源校验/落库且失败有终态；**M3** 教师 UI+最小 lease/取消/恢复（PLAN-15/16），取消生效且一次进程中断后显式恢复。三类 API（任务创建/单任务读取/报告读取）统一课程教师权限 `require_course_teacher`。完整 TTL 清理/Trace UI 可暂缓，失效来源不可继续解析。

- 定义教师调查任务边界：课程范围、时间窗口、问题类型、只读工具、结果结构和人工确认点。
- 明确任务状态、步骤状态、错误分类、取消、超时、恢复、重试、幂等和预算语义；具体字段先检查现有数据模型。
- 用固定 Fake/Replay 场景定义预期终态、Trace 事件、工具调用和禁止副作用。
- M1 Fake 必过：H01/H02/H03/H04/H05/H08/H09/H10 与 H-timeout；另验持久化创建后可读/无权拒绝。H06/H07/H11 在 M3；M2 报告/外发/空窗/E5-A；H12 失效来源在 M2/M3 验，物理清理可后置。完整映射见 [任务合同 §9](teacher-agent-task-contract.md#9-harness-首批场景与分期门禁)。
- 交付可运行的 Harness 最小骨架与可判定合同；恢复与持久化的真实行为由 PLAN-15 集成验收。

### PLAN-15：运行时可靠性与权限治理

- **15A 模型/迁移**：新增 `agent_tasks` 与 append-only `agent_task_events` 两表；步骤状态由 `(task_id, attempt, step_no)` 事件流重建，不先增加第三张 step 表。仅做 SQLite 隔离迁移测试与 PostgreSQL DDL 编译，不连接默认/正式数据库。
- **15B 事务存储**：实现规范化请求指纹、数据库唯一约束幂等、同一事务内状态/检查点/事件写入和单调事件序号；处理唯一约束竞态与确定性冲突；同课 queued/running/cancel_requested 最多 1 个活跃任务，新建冲突返回确定性错误。
- **15C 生命周期**：M2 先满足有界执行、累计预算与异常终态；M3 补最小执行 lease/token fencing、取消安全边界、stale running→interrupted 与显式恢复/重试。显式 retry 为同任务新 attempt，预算跨 attempt 累计，不静默整任务自动重试；预算/超时/finish 竞争按 [任务合同 §7](teacher-agent-task-contract.md#7-初始预算与可判定终止规则2026-10-26-用户确认)。完整 TTL 清理可后置；不隐式恢复，不把检查点当作模型生成的可信指令。
- **15D 权限/Harness**：随 M1/M2/M3 对应能力集成，不等 15C 全做完；工具固定 allowlist 与 schema，每次调用重新验证当前教师 membership、task.course_id、Document/Chunk 所属课程及 `retrieval_enabled`。使用 PLAN-14 Fake/Replay 验证对应阶段的终态、必要事件、越权、取消、恢复和预算。
- **15E 收口**：每批定向 pytest、ruff、`git diff --check`，同步任务卡与交接记录；报告 SQLite/Fake 与真实 PostgreSQL 并发测试的证据差异。完整调查流程与 UI 由 PLAN-16 承担。

### PLAN-16：教师课程问题调查 Agent

- 首版只做一个场景：在授权课程和指定时间窗口内调查重复问句、依据不足或系统失败。现有 QueryLog 未保存最终回答正文/实际引用快照，因此不宣称能回溯审计历史回答内容。
- 复用现有统计、问句分组、资料状态、检索和引用能力，不创建第二套 RAG。
- 报告区分观察事实、来源证据、候选原因、不确定点和建议人工动作；重要判断可回溯到问句、文档与页码。
- M2 报告 API 校验 schema/来源并落库，失败有终态；真跑路径未 confirm_external_processing 时创建前拒绝，外部 LLM/Embedding/语义分组计数各为 0（外部路径 spies）。空窗/无数据报告与 E5-A Fake 门禁必过。
- M3 沿已完成的视觉版式补教师外发确认、报告、取消与显式恢复；经 Vite 验发起调查 → 报告 → 依据 → 点引用 → 原 PDF 页，记录 Document/页码。来源删除/禁用/越权不得展示内容；完整 Trace UI 可暂缓。
- Agent 默认只读；正式资料、索引、成员和权限变更仍走现有业务界面并由教师/管理员确认。
- E5-A 用同课程/时间窗/样本快照的固定 Fake/Replay 对照 A 统计列表、B 相似组（若可用）、C 报告。必需事实有授权来源、捏造引用=0、候选原因当事实=0、no_evidence 不断言课件缺失、系统失败不归教学问题、终态正确；细则见 [任务合同 §9.2](teacher-agent-task-contract.md#92-e5-a-固定-fakereplay-对照与门禁)。开发者可核验；无真实教师不宣称效率已验证，真实模型质量单列。

### PLAN-17：课程业务基础

- 迁移和回归在隔离数据库执行；真实课程资料、正式库破坏性迁移须当次明确授权。
- 2026-10-26 **M4**（业务里程碑，非 Agent 第四期）：M3 基线 `4587421` 后已实现五件套 API 与最小前端入口；`0015`（父 `0014`）仅内存 SQLite 升降级、PostgreSQL 离线 DDL 编译，旧资料启用状态保留。CSV 使用管理员维护的已有学生账号，缺账号逐行报告；不自动建号。当前定向 **91 passed**（业务/迁移 22 + Agent 69）；build/Vite 与本地 commit 的实际结果见 [任务卡](tasks/PLAN-17-course-business-foundation.md) 和 [SESSION_STATE](tasks/SESSION_STATE.md)，不得据 API 绿测宣称完整 UI 验收。

## 六、开工纪律与证据口径

- 一次会话一个实现任务；纯文档重构可单独处理。
- 开工前检查 git status --short，保护用户未提交改动；不读 .env，不改金标，不重写历史证据。
- 真实 Embedding/LLM/Vision/reranker、外发真实问句、全量解析/重入库、破坏性迁移和大依赖下载均须当次明确授权。
- Fake/Replay 通过只证明控制流程合同；开发者观察不等于独立用户试用；开发者题目核验不等于独立答案核验。
- 每张新任务卡需写明实际路径、测试命令、原始输出摘要、未完成项与回滚/恢复说明。
- 新依赖需核对版本、许可证、传递依赖、运行成本和现有方案不足；优先复用成熟 API/组件，不整体迁移 RAG 框架。
