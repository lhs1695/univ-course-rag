## 目标与约束

面向高校各类课程，采用开源组件完成有依据、可核对的问答与课程适配。中期交付本机原型，结题争取小范围多人试用。中期前须验证普通文字、扫描页、公式、表格和图片/图表的有限代表样本；不要求建立任意格式、任意复杂页面的通用多模态平台。工程目标是**尽快用成熟开源能力补齐当前解析短板，而不是增加一个新的 RAG 平台**。

用户最新决定优先于本文，本文为唯一施工计划；研究目标见 [新开题资料](../新开题资料.md)，操作见 [workflow](workflow.md)，当前行为见 [engineering](engineering.md)，验收见 [validation](validation.md)。每项先记录具体复用对象、版本/许可与总成本，成熟能力优先直接调用，本地实现需有替代比较。

2026-10-17 清理卡：沿用已接入的 PyMuPDF 原生 API 与现有页级质量门禁，无新增组件或自写替代实现；仅删除退役代码与依赖声明、修正文档。验收为生产无残留导入、保留默认路径防 Docling 导入测试、Ruff、parse/ingest 相关测试及 diff 检查。venv 不卸载包；corpus/local 证据和两个 worktree 均保留，原因见当前交接。

### R7B-L1：恢复 PyMuPDF 默认入口与最小页级质量门禁（已通过）

**目标：** 用已有依赖恢复轻量 PDF 解析，避免为解析普通文字页增加模型与新运行环境；同时修复历史路径静默丢空页的问题。

1. 从项目历史实现恢复 PyMuPDF 的 `fitz + get_text("text")` 轻量路径；PDF 使用原生文字提取，不安装 OCR、Docling、EdgeParse、OpenDataLoader 或其他新依赖。PPTX/DOCX/Markdown/TXT 继续使用现有解析器。
2. 不再静默丢弃空页：质量报告必须保留原 PDF 总页数、连续的 1-based 页码、每页文字长度/空页/稀疏页/明显异常字符标记及文件哈希、解析器版本、总耗时。稀疏阈值先由已有 inventory 与代表页检查确定；阈值只作警告，不把短页直接判成错误。
3. 区分“解析过程是否执行成功”与“文字覆盖是否完整”。已知图像页可以在逐页登记并向 UI 明确展示覆盖警告的前提下，允许其余可读文字进入索引；不得把它显示成内容完整。文件无法读取、页数/页码映射不一致、意外的全空输出或不可恢复异常必须失败，且不得覆盖旧完整索引。
4. 继续使用现有 `(page, text)` 切分接口和 `semantic-text-splitter`，不要求 bbox/元素树，不将完整 PDF 或解析 JSON 塞进数据库。Chunk 必须能回到原文件页；空页不生成空 embedding，但必须留在质量报告中。
5. 调整与此入口直接相关的 Fake/单元测试，覆盖总页数/页码连续性、空页与稀疏页登记、全空/异常失败、部分覆盖警告、失败重试与旧索引保护。确认 ingest 状态与质量警告不会互相冒充；不在本项重入库或运行真实模型。

**通过门槛：** 无新增解析依赖；页数和页码可对账；空页/稀疏页不会静默消失；有可读文字的 PDF 仍能进入现有切分链路；预期图像页被标为覆盖不足而不是完整成功；致命解析错误不会替换旧索引；相关测试通过。

### R7B-L2：固定代表页核对（已通过）

**目标：** 用已有 inventory 和原 PDF 核对轻量解析结果，不启动新的解析器选型。

1. 固定少量页面，覆盖普通文字、线代公式、历史图文/表格、心理学图像页和哲学稀疏页；样本按风险选定后不因结果替换。
2. 对照原页检查文字缺失、阅读顺序、控制字符、公式/表格损坏、页码与引用；只记录真实观察，不用字符数替代内容正确性。
3. 复用 2026-10-16 的 17 份/344 页预检和来源 inventory；不为再次统计相同信息而先重跑全量解析。
4. 只对检查发现的具体缺口形成后续专项任务。OCR、公式识别、视觉调用都需明确页面范围与成本；本项不安装工具、不调用云。

**通过门槛：** 每类关键风险都有可复核的页号与结论；对暂不支持的图像/公式内容明确标注范围；没有因为工具宣传能力或整份文件字数正常就宣布通过。

### R7B-L3：17 份轻量离线冻结（已通过）

**目标：** 在不安装模型、不调用云、不写数据库的前提下，形成可恢复的 17 份/344 页轻量解析基线。

1. 运行前核对 17 份文件与 inventory 中的 SHA-256/页数；仅使用 PyMuPDF 原生文字提取，不运行 OCR、公式增强、表格模型或视觉模型。
2. 输出逐文件/逐页文字与质量报告、输入/输出哈希、parser 版本、总耗时、空页/稀疏页/异常页及明确的失败状态。真资料与产物仅放受控忽略区。
3. 为防止再次出现长时间无反馈，逐文件记录进度并设置**单文件 3 分钟、全量 15 分钟**硬墙钟上限（不含人工核对）；超限立即停止并汇报，不自动重试、不无限续跑、不开始下一阶段。
4. 若可读文字覆盖正常但部分页面为图像页，产物可冻结为“文字路径完成、存在未覆盖页面”的有限基线；不得把这类结果描述成完整多模态解析。

**通过门槛：** 17 份文件逐一有终态记录；所有页码与来源可对账；失败/空页/稀疏页有明确状态；总耗时在硬上限内；任何失败都不污染旧索引。未通过则只处理具体 blocker，不得进入 R7B-5。

1. 保留 Vue 3 + Element Plus，不更换 UI 框架、状态管理或 PDF 技术栈。
2. 优先打磨学生问答页：问题输入、回答状态、引用卡片、依据不足/系统失败、引用聚焦、原 PDF 页定位形成清晰的单页学习工作台。

**验收：** 核心页面视觉一致；学生能够完成“进入课程 → 提问 → 看回答 → 点引用 → 回原 PDF”的操作；失败、空状态和权限失效不会显示成成功。

### P7-2 课程与学生生命周期

现有模型和 API 已支持管理员创建课程、管理课程成员，教师在课程内加入已有学生，学生在“我的课程”进入已授权课程。因此中期采用最简单的受控流程：

管理员创建课程/账号 → 管理员或教师加入已有学生 → 学生进入我的课程 → 教师上传资料 → 学生问答

1. 不新增学生自主选课、公开课程目录、邀请码、申请审批等非核心流程。
2. 补齐管理员侧课程编辑/删除入口（后端已有能力时优先做 UI 闭环），删除需二次确认。
3. 课程成员变更必须立即影响下一次请求；学生只能访问当前已加入课程。
4. 教师只能维护自己有权限的课程；管理员维护课程和账号。
5. 不把课程/学生统计扩展成成绩、能力画像或个性化推荐。

**验收：** 至少用管理员、教师、学生三种角色各走一遍创建/授权/访问/撤权链路；课程删除不留下可访问的课程内容。

### P7-3 数据库与文件生命周期收口（R9 前置）

**当前状态（2026-10-18）：** 数据库 dump + 上传资料/解析产物的隔离恢复子项已通过，完整证据见本机忽略区 `corpus/local/r9-recovery-2026-10-18/`。本项其他生命周期门槛只按已有测试/实际记录判定；不以单次恢复通过冒充 P7 整体完成，也不以 Demo Reset 或成本/资源专项验收代替恢复实测。

1. 不更换 PostgreSQL + pgvector，不引入 Redis、Elasticsearch、MongoDB 等新基础设施。
2. 核对最新 Alembic migration 可从干净数据库建立；真实目标库在实施前单独确认迁移状态。
3. 核对课程、成员、资料、Chunk、问答记录的外键和删除语义；课程/资料删除不能留下可检索或可直接读取的旧内容。
4. 保持“数据库记录”和“上传文件”分开恢复；文件清理失败记录补偿状态，不在请求内无限重试。
5. 解析产物以受控本机文件作为事实源/恢复材料，业务库保存必要 metadata、来源、Chunk 和向量，不把完整解析 JSON 与所有图片二进制塞进 PostgreSQL。
6. 中期至少形成一次数据库 dump + 上传资料/解析产物恢复包，并在冻结前验证恢复；不使用 Docker volume 清空重建作为“恢复”。
7. 记录可重复的 Demo 数据恢复流程；它只操作明确的演示对象，不删除真实资料或历史结果。独立的 Demo Reset 自动化脚本是可选优化，不代替数据库与文件恢复实测。

**验收：** 干净库迁移、课程/资料删除、失败任务恢复和演示恢复均有明确操作记录；失败不污染新索引或覆盖旧完整索引。

**本轮恢复实测结果：** custom dump 已从 `univ_course_rag_r7b6_real` 恢复到全新隔离库 `univ_course_rag_r9_restore_20261018`；migration `0011`、4/17/385、全部 public 表行数、Embedding 身份、pgvector 最近邻查询、17 份上传 PDF 的存储边界/SHA-256/页数、17 份解析产物来源身份均通过。源库、旧库与 Fake 库未变；没有云调用或全量重入库。恢复包哈希、脚本与操作步骤见 `corpus/local/r9-recovery-2026-10-18/`（Git 忽略区）。

### P7-4 成本、资源与请求限制

中期不追求吞吐量，优先控制“单机演示 + 小规模实验”的最坏情况。所有真实 embedding/LLM/Vision/reranker 调用仍遵守当次授权。

| 类别 | 中期策略 |
| --- | --- |
| 解析 | 普通 PDF 使用现有 PyMuPDF 原生文字路径；不引入新解析器；OCR/公式/视觉按具体页面另立任务并设时间与资源上限 |
| Embedding | 固定模型与 batch；资料冻结后不因 UI/Prompt 小改反复全量 embedding |
| LLM | 固定题集、上下文上限、输出上限、超时和重试；评测达到预算即停止 |
| Vision | 默认关闭；只有固定少量视觉题在明确授权后调用，单独计量 |
| Reranker | 默认关闭；只有新 baseline 证明排序瓶颈后才启用 |
| API/文件 | 沿用现有文件大小、页数、问题长度、上下文和候选上限；UI 对用户可理解地提示主要限制 |

实际费用优先记录供应商响应中的 usage 或账单数据；没有可靠 usage 时不得猜算 token/费用。供应商价格和限流会变化，文档只保存本次实验实际采用的模型、版本、调用量和账单依据，不把历史价格写成永久合同。

### P7-5 运行、健康检查与 Demo 准备

1. 保持现有本机启动方式；补齐一份最短启动/检查顺序：数据库 → migration → backend → frontend → health/ready → 登录。
2. 健康检查只说明进程/数据库/配置状态，不把 configured 写成供应商连通或模型可用。
3. Demo 前固定课程、账号、资料和题目，避免临场重新解析、重新入库或临时换模型。
4. 准备“正常回答 + 引用核对”“资料外问题 → 依据不足”“服务异常 → 系统失败”“撤权/串课 → 拒绝访问”四类固定演示。
5. 录屏前重新登录、检查资料状态和数据库连接；不拍摄 key、Cookie、学生身份、原始答案或其他敏感内容。
