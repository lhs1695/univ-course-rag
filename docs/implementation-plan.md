# 结题施工计划与任务清单

更新：2026-10-26。本文是当前结题阶段的施工路线图；**已拍板决策摘要**见 [结题已拍板规格](结题已拍板规格.md)；产品范围以 [结题产品定义与完工标准](结题产品定义与完工标准.md) 为准，验收规则以 [结题验收标准](validation.md) 为准。任务状态必须由代码、测试与操作证据决定，不能由计划或旧任务卡标签推断。

## 一、已确认的方向与范围

1. **教师侧 Agent：必做主线，按 M1→M2→M3 薄切。** 场景锁死为课内问题调查：M1 合同 + Harness + 任务落库可读，M2 调查报告 API，M3 教师 UI + 最小 lease/取消/恢复；完整 TTL 清理与 Trace UI 不作为报告首交付的前置。
2. **课程业务基础：必做。** 按最小必要范围完善学期、班级、学生名单、个人主页及对应权限；教师与管理员资料协作按普通、清晰、可审计的业务流程实现。
3. **GraphRAG / 知识图谱：结题不做。** 全部主线（Agent M1–M3 + 业务最小集）完成并稳定后，才可考虑演示「锦上添花」；不单独立项开工，不阻塞验收。不上默认 LangGraph/LlamaIndex 编排框架。
4. **保留可信 RAG 主线。** 继续处理 Evidence Trace、误拒答、资料生命周期、权限和引用来源；Agent 不替代底层 RAG 质量诊断。
5. **验收边界已确认。** 用户独立试用已取消，采用脚本化测试与开发者 Vite 观察，并明确标注证据级别；空白机部署与备份恢复暂缓，不能写成已通过。

### PLAN-14：合同与 Harness 基线

分期口径（拍板）：**M1** 合同+Harness+任务落库可读（PLAN-14 与 PLAN-15 的最小存储/权限子集共同交付）；**M2** 调查报告 API（PLAN-16 前半）；**M3** 教师 UI+最小 lease/取消/恢复（PLAN-15/16 对应子集）。完整 TTL 清理/Trace UI 可暂缓，来源留存边界和服务端权限不得因此绕过。

- 定义教师调查任务边界：课程范围、时间窗口、问题类型、只读工具、结果结构和人工确认点。
- 明确任务状态、步骤状态、错误分类、取消、超时、恢复、重试、幂等和预算语义；具体字段先检查现有数据模型。
- 用固定 Fake/Replay 场景定义预期终态、Trace 事件、工具调用和禁止副作用。
- 首批覆盖正常调查、证据不足、空检索、工具异常、模型超时、取消、恢复、越权、预算耗尽、提示注入和重复执行。
- 交付可运行的 Harness 最小骨架与可判定合同；恢复与持久化的真实行为由 PLAN-15 集成验收。

### PLAN-15：运行时可靠性与权限治理

- **15A 模型/迁移**：新增 `agent_tasks` 与 append-only `agent_task_events` 两表；步骤状态由 `(task_id, attempt, step_no)` 事件流重建，不先增加第三张 step 表。仅做 SQLite 隔离迁移测试与 PostgreSQL DDL 编译，不连接默认/正式数据库。
- **15B 事务存储**：实现规范化请求指纹、数据库唯一约束幂等、同一事务内状态/检查点/事件写入和单调事件序号；处理唯一约束竞态与确定性冲突。
- **15C 生命周期**：M2 先满足有界执行、累计预算与异常终态；M3 补最小执行 lease/token fencing、取消安全边界、stale running→interrupted 与显式恢复/重试。完整 TTL 清理可后置；不隐式恢复，不把检查点当作模型生成的可信指令。
- **15D 权限/Harness**：随 M1/M2/M3 对应能力集成，不等 15C 全做完；工具固定 allowlist 与 schema，每次调用重新验证当前教师 membership、task.course_id、Document/Chunk 所属课程及 `retrieval_enabled`。使用 PLAN-14 Fake/Replay 验证对应阶段的终态、必要事件、越权、取消、恢复和预算。
- **15E 收口**：每批定向 pytest、ruff、`git diff --check`，同步任务卡与交接记录；报告 SQLite/Fake 与真实 PostgreSQL 并发测试的证据差异。完整调查流程与 UI 由 PLAN-16 承担。

### PLAN-16：教师课程问题调查 Agent

- 首版只做一个场景：在授权课程和指定时间窗口内调查重复问句、依据不足或系统失败。现有 QueryLog 未保存最终回答正文/实际引用快照，因此不宣称能回溯审计历史回答内容。
- 复用现有统计、问句分组、资料状态、检索和引用能力，不创建第二套 RAG。
- 报告区分观察事实、来源证据、候选原因、不确定点和建议人工动作；重要判断可回溯到问句、文档与页码。
- M2 先交报告 API；M3 教师沿已完成的视觉版式查看状态、步骤/事件摘要和结果，支持取消及按规则重试/恢复；完整 Trace UI 可暂缓。
- Agent 默认只读；正式资料、索引、成员和权限变更仍走现有业务界面并由教师/管理员确认。
- 与原始统计/问句列表基线比较证据覆盖、无依据推断、任务终态、调用量、耗时和费用；没有真实教师参与时不宣称用户效率已获验证。

### PLAN-17：课程业务基础

- 先盘点现有用户、课程、成员、资料、会话和日志表，不先写迁移。
- 梳理学期、班级、学生名单、个人主页与课程成员的关系及角色权限矩阵。
- 最小集固定为学期、班级、CSV 名单、极简个人主页（不展示提问历史）、资料两步启用检索；名单导入必做格式校验、重复处理与结果摘要。
- 资料协作为教师上传 → 管理员可见 → 管理员启用检索，两步完成；不额外堆叠复杂审批、消息通知或组织层级。
- 迁移和回归在隔离数据库执行；真实课程资料、正式库破坏性迁移须当次明确授权。

### PLAN-18：知识点关系 / GraphRAG（结题后可选备忘）

- **结题期明确不做** GraphRAG、知识图谱与完整关系层实现。
- 保留本条仅为备忘：仅当 PLAN-14～17 主线全部完成并稳定、且演示确需「锦上添花」时，再单独讨论小样本对照；默认结论仍是不做。
- 不因本条目排队占用工期；不阻塞教师 Agent 与业务基础验收。


## 五、推荐执行顺序

对齐 [结题已拍板规格](结题已拍板规格.md)：业务盘点与 Agent 运行时**并行薄切**；第一张可演示交付仍是调查报告；GraphRAG 不进本序列。

1. **文档与合同收口**：对齐拍板规格与任务卡，记录并保护工作区既有改动；中期答辩材料冻结不改。
2. **M1**：核对 PLAN-14 合同与 Fake/Replay Harness 的真实证据，结合 PLAN-15 最小存储/权限交付任务落库可读；现有半成品仅在用户确认后另卡处理，不以全工作区清空为前置。
3. **并行盘点**：PLAN-17 数据模型/权限盘点与 Agent 运行时薄切并行（不先写破坏性迁移）；课程级 Agent 先复用现有 course/member，不等待业务五件套全部完成。
4. **M2→M3**：PLAN-16 先交调查报告 API，再沿已完成的前端版式补教师 UI、PDF 引用回跳与最小 lease/取消/恢复；完整 TTL 清理/Trace UI 不挡报告首交付。
5. **补齐 PLAN-17 最小业务**：学期/班级/CSV 名单/极简主页/资料两步启用检索。
6. **RAG 附线与证据缺口**（授权后）：PLAN-06/07 有限校准；不默认 rerank、不上编排框架。
7. **结题收口**：本地运行说明、已知限制、验收记录；PLAN-10 空白机/备份恢复仍暂缓。
8. **（非结题）** PLAN-18 GraphRAG/知识图谱仅作主线完成后的演示锦上添花备忘，默认不做。

## 六、开工纪律与证据口径

- 一次会话一个实现任务；纯文档重构可单独处理。
- 开工前检查 git status --short，保护用户未提交改动；不读 .env，不改金标，不重写历史证据。
- 真实 Embedding/LLM/Vision/reranker、外发真实问句、全量解析/重入库、破坏性迁移和大依赖下载均须当次明确授权。
- Fake/Replay 通过只证明控制流程合同；开发者观察不等于独立用户试用；开发者题目核验不等于独立答案核验。
- 每张新任务卡需写明实际路径、测试命令、原始输出摘要、未完成项与回滚/恢复说明。
- 新依赖需核对版本、许可证、传递依赖、运行成本和现有方案不足；优先复用成熟 API/组件，不整体迁移 RAG 框架。
