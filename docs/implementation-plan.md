## 教师学情分析 V1 的交付定义

教师学情分析是结题前必须升级的产品能力，不是“有时间再做”的装饰功能。V1 必须能回答：

1. 这门课在选定时间窗口内，学生主要问了哪些问题，回答结果如何？
2. 哪些问句可能是同一个疑问，哪些只是同一知识点下的不同问题？
3. 这些问题可能关联哪个课程章节/知识点，标签是否经过教师确认？
4. 问题更可能需要补充资料、修复检索/引用、澄清问法，还是只是正常复习？
5. 教师核查后做了什么，资料/检索调整后，代表问题是否改善？

输出只作为课程级学习需求线索；当前数据不能支撑个人掌握度、成绩或挂科风险预测。外部 Embedding/LLM 处理问句仍需显式确认，合成样本不得冒充真实学情。

## 开源研究与复用决策

| 参考对象 | 研究内容 | 本项目采用原则 |
| --- | --- | --- |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 文档/切片状态、人工检查、停用和解析流程 | 借鉴生命周期与解析质量交互，不迁移整套 RAG 平台 |
| [Kotaemon](https://github.com/Cinnamon/kotaemon) | PDF 引用高亮、证据预览、低相关度提示 | 复用交互模式，适配现有 Vue 页面 |
| [Moodle Learning Analytics](https://moodledev.io/docs/5.0/apis/subsystems/analytics) | 指标—分析目标—洞察—行动及反馈闭环 | 借鉴分析流程，不复制依赖成绩/活动数据的个体预测 |
| [Open University 学习分析仪表板](https://iet.open.ac.uk/projects/student-la-dashboard) | 共同设计与用户研究 | 借鉴任务试用和用户参与评价 |
| [Arize Phoenix](https://github.com/Arize-ai/phoenix) | Trace、版本化数据集、实验对比与失败样本回流 | 先利用现有运行记录/题集，不默认部署完整平台 |
| [Jisc 学习分析规范](https://www.jisc.ac.uk/guides/code-of-practice-for-learning-analytics) | 透明、数据最小化、有效性、人工监督 | 将隐私、纠正和非惩罚性用途纳入产品验收 |

任何源码复用都必须核对版本、许可证、传递依赖和实际集成成本，并保留必要声明。执行顺序与仓库纪律见 [workflow.md](workflow.md)；研究目标详版见 [旧开题资料.md](../中期答辩材料/旧开题资料.md)。
