# Plan：univ-course-rag 第六期

状态：计划已修订；尚未开工；主线 **本机产品可解释性、数据边界与效果证据**
日期：2026-09-10
前置：第五期阶段 32–37 已完成，远端 CI 已成功；阶段 25 仍等待非开发者试用，不能由本期开发或维护者走位替代。

**施工纪律：** 一次会话只做一个阶段。当前真实使用条件仅为本机，因此本期优先让教师能判断资料是否真的可用、学生能核对答案来源、维护者能控制提问数据，并留下不依赖云服务的性能证据。除明确授权外，不 push、不调用云服务、不读取 `.env`、key、真课件或真实学生提问。pytest 始终使用 FakeEmbedder/FakeLLM。

权威顺序：本计划 > `docs/decisions/` > `docs/intent.md`。Cookie session、Postgres + pgvector、单次检索 + 单次生成、Fake 测试和无 LangChain/RAGFlow 仍是冻结事实。

## 1. 为什么做第六期

第五期已经使单实例后端具备清晰失败边界、受限资源使用、readiness 和 CI，但“入库成功”在教师界面上仍不等于“资料抽取质量足以支撑问答”；引用虽有文件名、页码和摘录，却不便回到受权限保护的原资料核对；数据库还会长期保留学生原问题。此时继续扩大模型、格式或部署范围，无法提升真实课程知识库的可信度。

本期聚焦可观察、可核对、可治理：让每一次资料入库和答案引用都能解释，让问题日志有明确生命周期，并在不调用云模型的前提下测量本机课程规模下的退化趋势。它直接补足产品质量，也形成适合 Python 后端面试的证据：数据模型、权限文件服务、受限维护操作和可重复基准，而不是“换更大模型”。

## 2. 本期目标

1. 教师能看到入库结果的安全质量信号（来源单位数、抽取字符数、切片数及明确的空/过短警告），并能从失败资料页使用已有受控重试入口。
2. 学生和教师能从回答引用回到自身有权限访问的原资料；文件服务不得把上传目录作为公开静态目录，也不得跨课程或越界读取。
3. 真实提问在数据库中的留存期限和清理方式明确、受配置上限和批量上限约束；教师学情只使用留存窗口内的描述性聚合。
4. 用合成、无敏感内容的数据留下本机检索与入库规模基线，区分正确性、延迟和资源趋势；不以一次小样本 100% 指标宣称泛化能力。
5. 完成后的 README、demo、测试与交接准确说明本机能力、限制和仍待独立试用的阶段 25。

## 3. 全期边界

- **只做：** 资料质量元数据、受鉴权的资料读取/下载、引用跳转、日志留存、显式受限清理、合成规模基线和相应 UI/测试/文档。
- **不做：** OCR/vision、旧二进制 PPT/DOC、自动调参、rerank、多 Agent、聊天历史、成绩或学生画像、生产部署、Redis/Celery/定时任务平台、JWT/localStorage、云模型自动测试。
- **数据边界：** 真课件、完整提问、答案、Cookie、Session ID、key、数据库转储和基准原始载荷不进 Git、普通日志或聊天。基准只保存合成输入的聚合指标；引用读取仍按现有课程成员权限校验。
- **阶段 25：** 本期可改善试用前体验，但不能把维护者点击、Fake 测试或本机评测写成非开发者试用；阶段 18/19 仍只由原有真实反馈规则触发。

## 4. 分阶段

### 阶段 38 — 入库质量信号与受控重试（下一阶段）

- **做：** 在不保存课件正文的前提下，为资料持久化可解释的解析/入库结果元数据：页或幻灯片等来源单位数、抽取字符数、最终 chunk 数；资料列表显示这些信号。对零文本、零 chunk 或低于明确且有界阈值的文本给出“可能不适合问答”的提示，而不是将其伪装成解析失败。为失败资料显示已有的教师受控重试操作，并保持运行中、活动租约和权限限制。
- **不做：** 不按“字符少”自动删除资料、不将启发式质量提示当作检索质量结论、不展示正文或切片、不改变切分/embedding 算法、不新建后台任务平台。
- **证明：** `test_ingest.py` 覆盖 PDF/PPTX/DOCX/文本的安全元数据、空/过短提示、失败后显式重试、旧完整索引保持和学生拒绝；资料 API 的响应模型不回显正文。运行直接相关 pytest、仓库根 `python -m ruff check`、前端 `npm run build`，并仅实际点击一次新增重试或质量提示控件。

### 阶段 39 — 引用到原资料的受鉴权追溯

- **做：** 新增只允许课程成员读取的资料内容/下载端点，并经集中存储边界验证路径。问答引用提供资料入口；PDF 保留页码定位信息，其他格式只承诺打开原文件，不伪造页内定位。设置安全的 `Content-Type`、文件名和 `Content-Disposition`，使上传资料不会作为任意公开静态资源暴露。
- **不做：** 不在数据库保存重复文件正文、不提供跨课程搜索或分享链接、不为 PPTX/DOCX 做浏览器转换预览、不信任数据库中的路径、不绕过 HTTP-only Cookie 鉴权。
- **证明：** 测试覆盖同课学生/教师可访问、未登录 401、非成员或其他课程 403/404、越界/不存在存储路径安全失败，以及引用响应仅指向本课资料。运行 `test_storage.py`、`test_ask.py`、直接相关 API 测试与 Ruff；前端构建通过并仅点击一次引用资料入口。

### 阶段 40 — 提问日志留存与有界维护

- **做：** 为 `QueryLog` 建立本机可配置、合理上下界的留存天数与单次清理上限；提供仅管理员可触发的显式维护入口或本地 CLI，先支持 dry-run，再显式删除。删除以创建时间排序、批量受限，只记录数量和稳定分类；学情自然只聚合留存记录。记录其不会立即从外部备份中抹除的限制。
- **不做：** 不把问题原文发送给第三方，不做学生个人档案、个体画像或教师查看用户身份，不在每个请求扫描全表，不引入定时任务平台，也不承诺法律合规认证。
- **证明：** 测试覆盖未到期日志保留、到期日志多批删除、上限余留、dry-run 不修改数据、非管理员拒绝和日志不含 query/user/session 内容。运行直接相关 pytest 与 Ruff；若新增管理 UI，前端构建并仅点击一次新控件。

### 阶段 41 — 合成规模基线与回归证据

- **做：** 新增显式运行的本机基准入口或夹具，生成不含真实课件/问题的课程、资料和切片，记录不同切片规模下的入库批处理和检索延迟、返回数、数据库路径及环境摘要。结果只存聚合统计和脚本版本；为 pgvector 路径保留独立标记的本机 Postgres 证明。定义可比较但不过度严格的回归判读规则。
- **不做：** 不在 pytest/CI 做不稳定的时间断言，不调用 SiliconFlow/DeepSeek，不改 `top_k`、`min_score` 或索引算法以追逐一次结果，不拿开发机数字承诺生产容量。
- **证明：** 合成数据可重复生成、不会落入 Git 或上传目录；Fake/SQLite 正确性回归通过；显式 Postgres 基准能完成并输出脱敏聚合报告。运行相关 pytest、Ruff，以及一次维护者本机批准的基准命令。

### 阶段 42 — 本机产品收口与试用准备

- **做：** 更新 README、demo、资料页和问答页文案，明确质量提示的含义、引用追溯范围、提问留存窗口和本机基准的局限。按现有 demo 用夹具完成一次教师上传/重试、学生引用核对、拒答、学情和留存维护走位；将仍需非开发者独立完成的任务直接链接到阶段 25 模板。
- **不做：** 不代替非开发者完成试用，不把合成基准或 22 题真评测写成泛化准确率，不进入部署、OCR 或 RAG 调参。
- **证明：** 相关 pytest、Ruff、前端构建、CI 通过；新增控件各实际点击一次。交接文档明确阶段 25 仍在等待，且阶段 18/19 未触发。

## 5. 顺序与停止条件

**38 入库质量 → 39 引用追溯 → 40 日志留存 → 41 合成基准 → 42 本机收口**。

每阶段仅在其证明通过后提交并停止。若阶段 38 发现现有解析器无法稳定提供某类元数据，先缩小为已可靠的信号并记录限制，不编造质量分数；若阶段 39 的安全文件服务无法在现有权限模型内实现，停在设计审计，不将上传根目录公开。第六期完成后不自动进入部署、模型优化或阶段 18/19；新真实反馈或明确的远程使用目标另立计划。
