# 结题验收标准（现行摘要）

更新：2026-10-20。本文规定结题前的验收分层与必须留存的证据。完整历史协议见 [archive/validation-full.md](archive/validation-full.md)；产品范围和产品级完工门槛见 [结题产品定义与完工标准.md](结题产品定义与完工标准.md)。

## 1. 已有证据与边界

| 层级 | 已有/用途 | 不能宣称 |
| --- | --- | --- |
| Fake pytest | 权限、入库、检索合同、拒答路径 | 真实语义效果 |
| 本机联调 | cn_v2 + 真实/指定后端，按 [中期演示运行卡](中期演示运行卡.md) 执行 | 通用课程效果、独立试用 |
| 弱规则题集 | 预期文档/页命中、拒答 | 人工事实正确率 |
| 真实模型小样本（22 题） | Dense/Hybrid 分层指标；verifier=developer，见 [结果报告](../中期答辩材料/研究证据/results/retrieval-compare-2026-10-20.md) | 独立评测、普遍效果、Hybrid 显著优于 Dense |
| 彩排 PASS | 2026-10-20 核心演示路径复彩排；PERM 与系统故障路径另有截图/日志证据 | 生产可用、录屏已完成 |

当前中文四课基线为 4 门课程、27 份 PDF、2,501 chunks。COVERAGE_INCOMPLETE 20/27 表示存在需要核对的页面/覆盖警告，不代表 20 份文件均解析失败。22 题结果属于开发者核验，不是独立评测；指标分母和解释见 [评测登记](evaluation-results.md)。

## 2. 通用验收规则

- 任务开始前冻结题集/样本、标签规则、环境、配置、指标分母和目标阈值；不能看完结果后倒改标准。
- 每项结论保留原始输入、配置/版本、结果、失败案例和核验者；报告 n/N，不把不同指标合并为单一准确率。
- Fake、真实模型、开发者核验、独立核验、真实用户试用分别标注；一种证据不得替代另一种。
- 失败结果是研究证据，不得为通过验收而隐藏、删除或改写失败样本。
- 真实云 Embedding/LLM/reranker 调用需当次明确授权；未授权时用 Fake 或既有结果，不执行计费请求。

## 3. 检索与答案质量

- Dense 为基线；按相同语料、题集、模型与证据预算比较 Hybrid 和可选 reranker。
- 分别报告候选召回/排名、最终证据、事实要点、引用支持、严格来源定位、正确拒答、应答题误拒答、系统失败、首事件/端到端延迟和调用代价。
- 保留关键词独有候选、分数门槛和证据准入原因，避免只看最终答案猜测根因。
- 引用存在不等于引用支持，引用支持不等于严格命中预期页，检索命中不等于答案正确。
- PROB-F02 等失败案例须按资料覆盖、候选召回、证据过滤、上下文装配、生成和引用展示逐层定位；修复后使用相同题目回归。

## 4. 教师学情分析验收（结题必做）

本项目当前以课程问句、提问时间、问答结果、检索 chunk 标识和耗时为主要数据；未稳定接入成绩、作业、测验或出勤等学习结果。因此本阶段验收的是**课程级学习需求与问答障碍分析**，不是个体掌握度预测。

### 4.1 数据与指标

- 所有统计必须受课程权限与明确时间窗口约束，并显示时间范围、样本量、指标定义和数据留存窗口。
- 至少区分提问次数、不同问句数、引用回答、依据不足、系统失败及各自分母；系统失败不得被统计成知识缺口。
- 页面至少包含概览、主题/知识点分布、待处理线索；若系统对线索排序，必须显示触发原因，不能输出不可解释的单一“学情分数”。
- 教师视图默认不展示学生姓名、个人排名或个体问句轨迹；底层仍存在 user_id 关联时，不得宣称数据已完全匿名化。
- 小样本必须标注样本有限；不得由提问频率直接推断学生掌握程度或教师教学质量。

### 4.2 语义分组与知识点分析

- 语义分组展示代表问句、成员问句、频次、最近出现时间、结果分布、分组阈值与模型身份；单例和未分组问题需保留。
- 建立人工标注样本，至少区分同一疑问的不同表达、同一知识点但不同意图、语义相近但意图不同、无法判断。
- 正式评价前冻结标签规则与目标阈值；报告成对精确率/召回率或适用聚类指标、覆盖率、单例比例、误合并/误拆分案例。
- 自动分组、问题意图和知识点标签默认都是候选。未通过质量门槛或未被教师确认时，不作为确定的课程盲区或教学结论。
- 真实日志不足时可用合成/研究样本验证功能，但必须清楚标注数据来源，不得冒充真实学生学情。

### 4.3 教师处理闭环

- 教师可确认或修正分组/知识点标签，并记录核查状态、处理动作、备注、处理人和时间；刷新后记录仍存在。
- 至少支持无需修改、补充/澄清资料、重新处理索引、调查检索/回答问题、继续观察/无法判断等动作。
- 教师能够从主题/线索跳转至代表问句、可用回答结果与来源资料，并能看清当前标签是系统候选还是教师已确认。
- 至少完成一条端到端闭环：问题候选 → 教师核查 → 记录行动 → 更新资料/检索或说明无需修改 → 对代表问题回归。
- 评价分组质量时，教师接受率/修正率只能作为辅助信号，不能单独替代人工标注指标。
- 向外部 Embedding/LLM 发送原始问句必须显式确认并说明范围、用途和保留方式；遵守既有查询日志留存与清理规则。

## 5. 流式体验与性能工程验收（结题必做）

- Fake 模型下验证流式事件顺序、结束状态唯一性、错误传播、客户端取消、超时清理和并发请求隔离。
- 至少在并发度 1、5、10 的可重复测试中记录成功/失败数、吞吐、首事件延迟和端到端耗时；测试环境、请求分布和 Fake/真实模型必须明确区分。
- 对真实模型做测量时记录模型、检索/提示词配置、测试时间、用量与失败；需要新的真实云调用时先取得当次授权。
- 报告 p50/p95 延迟、错误率、环境和负载范围。没有代表性压力测试和明确目标时，不宣称“高并发”或生产级容量。

## 6. 权限、资料生命周期与用户体验

- 对学生、教师、管理员执行角色矩阵与课程隔离测试；直接 API、检索结果、引用与原文件入口均覆盖。
- 测试上传、失败重试、停用/替换、删除、并发入库和索引更新；确认数据库、文件、chunks、向量与引用状态一致，清理失败可见且可重试。
- 由未参与开发者完成预先定义的学生端和教师端任务，记录完成情况、核对来源的耗时、主要困惑和失败点。若无法招募，明确记录未完成及限制。
- 用户测试至少覆盖：学生提问并核对引用；学生遇到依据不足/系统错误后能理解下一步；教师检查资料质量；教师审查一组学情分析候选并记录处理动作。
- 修改核心路径后复测阻断任务的问题；主观满意度不能替代任务完成证据。

## 7. 发布验收与交付

- 在干净环境按照文档完成配置、依赖安装、数据库迁移、启动、基础任务与恢复演练。
- 交付自动化测试结果、冻结题集与标签规则、原始评测结果、失败分析、学情分析人工标注/评价、性能报告、用户任务记录、运行与恢复文档、许可证与数据公开边界清单。
- 任何未达到的门槛如实记录为限制；最终发布前冻结代码版本、配置、数据基线与测试结果。
