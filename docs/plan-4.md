## 2. 本期必须解决的真实观察

### 2.1 最终拒答没有进入“未命中 / 拒答”

当前 `QueryLog.hit` 表示检索器是否返回片段。阶段 17 删除 PPTX 后，剩余 PDF 的泛化编程片段仍越过 `0.15` 阈值，因而 `hit=True`；DeepSeek 没有给出合法引用并自行拒答，学情却仍把该问句归入高频命中。

第四期合同：

- `hit` 保留为检索层遥测，不改写其历史含义。
- 对用户而言，只有至少一个经过白名单过滤的引用才算可靠回答。
- 有检索片段但没有合法引用时，API 返回现有 `NO_EVIDENCE` 契约，丢弃无引用答案；学情归入“未命中 / 拒答”，不再归入高频命中。

### 2.2 `embedding_model` 不能区分 Fake 与云向量

当前 FakeEmbedder 与 SiliconFlowEmbedder 都可能把 `BAAI/bge-m3` 写入 `Chunk.embedding_model`，但二者不在同一向量空间。只比较模型字符串不足以保证兼容。

第四期合同：索引身份至少包含 **backend + model + dimension/version**。查询只能比较兼容索引；发现旧索引或混合索引时明确提示重新入库，不静默伪装成普通无依据。

### 阶段 22 — 有引用才算可靠回答

- **做：** 保留 `QueryLog.hit` 作为检索遥测。若检索为空，沿用“不调用 LLM + `NO_EVIDENCE`”；若调用 LLM 后没有任何合法引用，则丢弃无引用答案，同样返回 `NO_EVIDENCE`，但日志仍可通过 `hit=True` 与 `error_code=NO_EVIDENCE` 表达“召回了但没有形成可靠答案”。教师学情的高频问句仅统计 `error_code is None` 的可靠回答，“未命中 / 拒答”继续按 `NO_EVIDENCE` 统计，避免同一日志同时进入两表。沿用现有 API 字段，不为此新增数据库迁移。
- **不做：** 不通过关键词猜模型是否在拒答；不接受无引用的课内事实答案；不修改检索阈值；不改黄金题正文。
- **证明：** 在 `test_ask.py` 增加“有 hits 但 LLM 无引用”和“只有非法引用”均确定性拒答；保留“非法引用 + 合法引用”只留下合法引用。`test_insights.py` 证明 `hit=True + NO_EVIDENCE` 只进入拒答表。运行 `pytest backend/tests/test_ask.py backend/tests/test_insights.py` 与仓库根 `python -m ruff check`。若改 UI，只在浏览器复验一次无引用拒答提示。

### 阶段 23 — 向量索引身份与不一致保护

- **做：** 为 Embedder 协议区分“调用供应商使用的模型名”和“持久化索引身份”。索引身份包含 backend、模型、1024 维及实现版本；入库写入现有 `Chunk.embedding_model` 字段，旧的裸模型名按 legacy/stale 处理。检索只使用与当前 Embedder 身份一致的切片；课程有切片但没有兼容切片时返回稳定的 `EMBEDDING_MISMATCH`（或等价明确契约），不调用 LLM。教师资料页或问答页显示“向量模型已切换，请从原文件重新入库”，不自动偷偷重算。
- **不做：** 不根据向量长度猜来源；不同时比较不同向量空间；不新增云厂商；不做批量 worker。重建仍采用教师删除后从原文件重新上传。
- **证明：** 测试覆盖 Fake/云同模型字符串仍为不同索引身份、只召回兼容切片、不一致不调用 LLM、课程隔离不回退。运行 `pytest backend/tests/test_ingest.py backend/tests/test_retrieve.py backend/tests/test_ask.py` 与仓库根 `python -m ruff check`；若改前端，运行 `npm run build` 并点击一次新提示。真实 key 不用于单测。

### 阶段 24 — 独立真模型评测与阈值校准

- **做：** 新增 `docs/eval-protocol.md` 和显式运行的本地评测入口。评测集建议 20–30 题，覆盖 PDF/PPTX 单点事实、跨页归纳、中文问英文资料、相似但无答案、完全无关、删除前后对照。至少记录正确文档 Recall@k、有效引用率、应拒答准确率、错误类型和延迟分位数。云评测必须显式传入允许联网/计费的开关，默认 dry-run 或拒绝运行；结果只保存汇总，不记录 key、完整私密课件或真实学生问题。
- **不做：** 不让 pytest/CI 调云；不把调参题混入既有黄金题；不为了提高分数删除失败样本；不先拍脑袋修改 `top_k=8`、`min_score=0.15`。
- **证明：** 先固定问题、预期文档和拒答标签，再运行评测；输出可复核的逐类统计和失败清单。只有评测证据显示稳定收益时，才单独提交阈值调整，并补跑 `test_retrieve.py`、`test_ask.py` 与 Ruff。
