## 目标与时间

- 汇报：约 6–8 分钟；产品实走：约 3–5 分钟。
- 只证明本机四课文本型问答原型、引用跳转、失败状态与已验收的权限边界。
- 不宣称人工事实正确率、通用多模态理解、生产部署或非开发者独立试用。

## 演示前检查

1. 启动本机 PostgreSQL；目标库必须是 `univ_course_rag_cn_v2`，migration `0011`，规模 **4 门课 / 27 份 PDF / 2,501 chunks**。课程名：线性代数、概率论与统计学、人力资源管理、教育学原理。
2. 在启动后端的 PowerShell 终端中，**进程级**设置：
   - `DATABASE_URL`：保留本机原连接串，只把数据库名改成 `univ_course_rag_cn_v2`（可用 `corpus/local/demo-merge-2026-10-19/restart-demo.ps1`）。
   - `UPLOAD_DIR`：指向 `corpus/local/cn-replace-2026-10-18/rechunk/uploads_v2`。
   - `QUERY_EXPANSION_BACKEND=llm`，`RERANKER_BACKEND=disabled`，`RETRIEVAL_STRATEGY=dense`。
   - **不要**修改 `.env` 并提交密钥。
3. 从仓库根启动后端：

   ```powershell
   backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
   ```

4. 在 `frontend` 目录运行 `npm run dev`，浏览器访问 `http://127.0.0.1:5173`；登录必须走 Vite，不直连 `:8000`。
5. 检查 `/health`、`/ready`；`/runtime` 应报告 database=available、reranking.backend=disabled。`configured` 只代表本地配置状态，不代表模型供应商连通。
6. 确认 `student` 已加入四门演示课。不要使用隔离恢复库或旧库 `univ_course_rag_r7b6_real` / `univ_course_rag_cn_v1` 当正式演示库；不要重新入库、临场换模型或启用 rerank。

**任一步失败就停。** 不在答辩现场排查密钥、重建数据库或临时重跑全量评测；改用下方备用截图并说明实际边界。

## 建议演示顺序

| 顺序 | 操作 | 预期 / 讲解重点 |
| --- | --- | --- |
| 1. 学生正常问答 | 登录 `student` → 我的课程 → **线性代数** → 提问 LA-01 | 有回答与引用卡片；点引用打开原 PDF 对应页（URL 含 `#page=`）。讲清楚引用用于回到原文核对，不等于主张已被证明。 |
| 2. 依据不足 | 仍在线性代数课，提问 LA-R | 问句见下；预期 `NO_EVIDENCE` / 依据不足；不能编造 SQL 或数据库步骤。 |
| 3. 教师一眼 | 登录 `teacher` → 线性代数 → **课程资料** 与 **问答反馈** | 资料列表可见入库状态；反馈页可见计数/趋势。不强调「抽取文本较少」类文案（已去掉）。 |
| 4. Admin 系统状态 | 登录 `admin` → **系统状态** | 只展示三行状态表（数据库 / 向量模型 / 生成模型）与刷新；无总判断黄条。 |
| 5. 失败与重试（可选） | 优先展示既有截图；若现场时间充足再实走 | 已提交问句后制造后端中断，页面显示系统失败而非「依据不足」；「重试本次问题」必须发送原已提交问句。 |
| 6. 权限边界（口头） | 说明既有 API 验收 | 撤权后不得再问该课；同名 PDF 不得跨课串读。不要为了演示随意删课。 |

固定问句（取自 cn 题集已通过项）：

- **LA-01（有引用）**：`根据线性代数讲义，线性代数主要研究哪两类对象？`  
  预期：作答并引用 `01-linear-algebra-full.pdf` 附近页；答案弱校验常含「向量空间」「线性变换」（弱规则，非人工正确率）。
- **LA-R（拒答）**：`根据线性代数讲义，如何用 SQL 创建数据库表并插入数据？`  
  预期：`NO_EVIDENCE` / 依据不足。
- **可选宽泛题**：`如何解线性方程组`（同课）——演示查询扩展后仍应回到步骤/正文页；属已验收路径，有 LLM 波动时勿现场连试。
