## 2. 标注定义与争议处理

标注单位是同一课程上下文中两个**不同问句 ID 的无序对**。同意图须兼具同一具体疑问/知识对象与同一任务；只有 `concept` 等粗意图相同不够。

| 标签/错误 | 冻结定义 | 例子/边界 |
| --- | --- | --- |
| `same` | 同一疑问的不同表达，可用相同核心解释或步骤回答 | PLAN-04 A1/A2 |
| `different` | 知识对象或实际任务不同，不能用同一核心回答替代 | PLAN-04 B1：特征值定义 vs 求解步骤 |
| `uncertain` | 缺上下文、表述残缺或争议未解决，不能可靠判同/异 | 不硬猜；保留原因，排除成对评分 |
| 误合并 `mis_merge` | `different` 对被分配到同一非空簇（FP） | 记录对 ID、原标签、分配、理由 |
| 误拆分 `mis_split` | `same` 对未分配到同一非空簇（FN） | 含一方/双方未分组，须单列原因 |
| 未分组 `ungrouped` | 在已冻结合格样本清单内，但 `cluster_id=null` | 不等于被排除的失败日志；也不等于单例 |
| 单例 `singleton` | 非空簇内仅一个不同问句 | 正常保留可见，不能自动判错 |

人工先看问题与课程上下文，尽可能隐藏模型分组；两位标注者分别记录标签/理由/时间，再比较分歧。第三位核验者复核，保留初标、分歧、裁决、理由和版本；无人裁决则 `uncertain`，不得多数猜测或让模型裁决。若只有开发者自标，写 `developer`，独立核验留空。本轮只有合成预设标签，没有执行双人标注。

知识点/主题标签独立检查：对照教师大纲或知识点表，记录来源版本、标签是否支持、过宽/过窄/错误/不确定及修正建议；无大纲为 `pending_taxonomy`。此列不得以分组正确或教师点“确认”代填。意图 `rule_v1` 的人工检查也独立记录，所有自动输出仍为 candidate。

## 3. 计算合同（每项都报告 n/N）

对已判定（`same` / `different`）的唯一无序对：预测同组 = 两端 `cluster_id` 都非空且相同。两个 null **不**算同组。不推断未标对，不通过传递关系扩充金标。

| 人工标签 | 预测同组 | 预测不同组/未分组 |
| --- | --- | --- |
| same | TP | FN |
| different | FP | TN |

| 指标 | 分子 n | 分母 N |
| --- | --- | --- |
| 成对精确率 | TP | TP+FP（已标且可判定的预测同组对） |
| 成对召回率 | TP | TP+FN（人工 same 对） |
| 误合并率 | FP | TP+FP |
| 误拆分率 | FN | TP+FN |
| 覆盖率 | 处于大小≥2 的簇中的不同问句数 | 全部合格不同问句数 |
| 单例比例 | 处于大小=1 的非空簇中的不同问句数 | 同上（不是单例簇数/总簇数） |
| 未分组比例 | null 分配问句数 | 同上 |

PLAN-01 §5 精确率行的文字说明与召回分母重叠；本协议将名称落实为上述标准混淆矩阵公式，**不改 metrics-v1 的数值门槛、样本门槛或既有标签**。精确率与召回率不能都用人工 same 对作分母。

零分母输出 `value=null`，报告写“不可计算”，不写 0% 或 100%。不确定对数/总标注对数单列；有效标注对 n = TP+FP+FN+TN，n<30 不申报阈值通过。即使合成对≥30 也不能支持真人质量主张。覆盖+单例+未分组分子之和应等于 N；无硬覆盖率门槛。误合并/误拆分各列至少 3 例（若发生且足够）；少于 3 例全部列出并写实际数量，不能补造案例。

范围须与待评系统输出一致：`question_groups._load_samples` 当前取本课、学生角色、窗内 `cited_answer/no_evidence`，空白问句排除；按完整文本折叠空白合并。失败/未知结果不进分组分母，单独记排除次数。`insights.py` 描述层有 200 字截断及 `NEEDS_CONTEXT/INVALID_QUESTION` 过滤，不能把其不同问句总数直接套作分组 N。PLAN-01 的小写去重约定与当前分组未小写实现差异须记录；正式导出先冻结去重映射并审查差异，禁止在跑分时静默重算或丢弃成员。本框架不改业务范围，合成问题没有这些差异。

## 4. JSON 与离线复算

入口：[`analytics_evaluation.py`](../backend/app/services/analytics_evaluation.py)。顶层必需字段 `sample_version`、`evidence_level`、`config`、`assignments`、`labeled_pairs`；可附 `questions`（ID/文本与来源）。

- `assignments`：每个合格不同问句恰好一行 `{question_id: 非空字符串, cluster_id: 非空字符串或 null}`。保留全部单例和未分组，禁止只导出“好簇”。簇 ID 仅在本次快照内比较。
- `labeled_pairs`：`{left: 问句ID, right: 问句ID, label: same|different|uncertain}`，可附 basis。重复/反向重复、自配对、未知 ID、非法标签/ID 报错，不静默忽略。结构缺键也失败。
- 配置记 metrics 版本、grouping_contract、intent_source、min_similarity、threshold_calibrated、模型名/身份、分配来源、课程/时间窗/筛选与去重版本。工具原样输出元数据，不认证其真实性。
- 纯函数 `evaluate_pairs`、`evaluate_assignments` 也可直接调用。输出含混淆计数、n/N/value、错误对和单例/未分组 ID，排序稳定；不写输入、不生成金标、不作达标判断。

仓库根执行（不加载 app 配置、dotenv 或 provider）：

```powershell
backend/.venv/Scripts/python.exe backend/app/services/analytics_evaluation.py backend/tests/fixtures/plan06_analytics_synthetic_v1.json
```

将 stdout 原样保存为该轮统计 JSON，再按[报告模板](analytics-validation-report-TEMPLATE.md)填写来源、人工核验、限制与原始文件哈希。当前合成预期算术：TP/FP/FN/TN=1/1/1/2，precision=1/2，recall=1/2；覆盖3/8，单例3/8，未分组2/8，不确定1/6。仅验证计算，不是算法表现。
