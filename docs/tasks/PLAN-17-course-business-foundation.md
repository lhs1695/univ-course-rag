| 项 | 值 |
| --- | --- |

| 状态 | draft |
| 须授权 | 破坏性迁移、正式库数据修改、真实学生名单导入须当次明确授权；先盘点与设计，不先迁移 |

## 目标

- 盘点并完善学期、班级、学生名单、个人主页与课程成员之间的最小业务模型。
- 明确学生、教师、管理员的业务权限和可见范围。
- 资料协作固定为教师上传 → 管理员可见 → 管理员启用检索的两步流程。

业务盘点与 Agent 运行时薄切并行；不以五件套全部完成为调查报告的前置。后续页面跟随已视觉通过的版式增补，不重开前端翻新。

## 非目标

- 不新建平行的 users/courses 身份或课程体系。
- 不在没有需求证据时建设复杂组织层级、审批流、消息通知或学习分析预测。
- 不在本卡顺手实现教师 Agent；与 PLAN-15/16 通过清晰接口协作。
- 不在正式演示库直接试验破坏性迁移。

## 验收标准

- [ ] 先形成现有 users、courses、course_members、资料与问答日志的数据关系盘点。
- [ ] 学期含名称与起止，课程可挂一个学期；班级为课下行政班，学生经名单进班并成为 `course_members`；先核对字段/关联/权限矩阵，再决定是否需要迁移。
- [ ] CSV 名单为必做，字段为学号/姓名/班级；校验空行与重复，提供失败/导入结果摘要。本课教师或管理员可导入，不能跨越课程权限。
- [ ] 教师、管理员和学生的关键业务路径有服务端权限测试；不能只靠前端隐藏入口。
- [ ] 极简个人主页只展示姓名、学号、角色、所属班级，不展示提问历史。
- [ ] 教师限本课上传与查看；上传后管理员可见，由管理员启用检索；启用前不得被普通检索或 Agent 工具读作证据。删除/禁用沿用现有软禁用思路，不增加审批层级。
- [ ] 管理员负责启用检索、全站账号与学期；关键接口按上述权限矩阵验证。
- [ ] 迁移在隔离数据库验证，旧数据读取兼容；定向测试、ruff、前端 build 与关键 Vite 路径按改动执行。
- [ ] 文档更新产品合同、架构说明、当前交接与任务卡，记录未实现项和数据迁移风险。

## 约束

- 先调查再定 schema；不得预设当前模型没有已有的学期/班级字段。
- 复用现有 PostgreSQL/Alembic、Session 与课程成员权限。
- 真实名单、正式库数据、破坏性迁移和外部数据导入须当次授权。
- 不把课程级问答统计解释为个人成绩或知识掌握度。

## 禁止改动的路径

- .env、密钥、Cookie/Session 明文、.git、venv、node_modules。
- 评测金标、用户未提交改动、未经授权的 corpus/local。
- 正式演示数据库及无关 RAG 检索逻辑。

## 验证步骤

1. 检查 git status 和当前授权；不读取 .env。
2. 阅读现有 SQLAlchemy 模型、迁移、API 与页面，绘制当前数据关系。
3. 先提交数据模型/业务流程建议，再实施获准的最小改动。
4. 在隔离数据库验证迁移、旧数据兼容、权限和回滚路径。
5. 运行定向 pytest、ruff、前端 build 和相关 UI 路径；贴原始输出与未完成项。
