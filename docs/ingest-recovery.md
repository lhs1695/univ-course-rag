# 阶段 29：入库批处理与恢复合同

日期：2026-09-09

## 状态与租约

| 当前状态 | worker 行为 | 教师重试行为 |
| --- | --- | --- |
| `pending` | 通过条件更新原子认领，写入唯一 `run_token` 后转 `running` | 未超时返回 409；超时后撤销旧 token、重置为 `pending` 并重新调度 |
| `running` | 每完成一个嵌入批次，用当前 token 刷新 `updated_at` | 未超时返回 409；超时后撤销旧 token 并重新调度 |
| `failed` | 不再自动运行，错误经过脱敏并截断 | 可立即重置并重新调度 |
| `succeeded` | 不重复处理 | 返回 409 |

worker 的心跳、成功提交和失败落库都必须匹配当前 `run_token`。旧 worker 在租约被恢复操作撤销后，即使重新运行，也不能刷新心跳、覆盖新状态或提交切片。

## 批次与事务

- `EMBEDDING_BATCH_SIZE` 默认 32，允许 1–256；只限制单次供应商请求，不改变切片算法。
- 每批立即校验返回数量和 1024 维度，完成后刷新任务心跳。
- 全部批次成功后，才在一个事务中删除旧切片、写入整套新切片并把任务置为 `succeeded`。
- 任一批次、维度校验或最终写库失败都会回滚新切片；已有完整索引不会被失败处理额外删除。

## 受控恢复入口

课程教师可调用：

```text
POST /courses/{course_id}/documents/{document_id}/retry
```

成功接受恢复返回 202，并通过现有进程内后台任务重新执行。失败任务可立即恢复；`pending/running` 默认超过 `INGEST_STALE_SECONDS=900` 才可恢复。学生返回 403，其他课程或不存在的资料按 404 处理，活跃或已成功任务返回 409。

该入口解决本机进程崩溃或热重载后任务永久卡住的问题，但仍不是持久化队列：恢复需要教师显式调用。第四期继续不引入 Celery 集群。
