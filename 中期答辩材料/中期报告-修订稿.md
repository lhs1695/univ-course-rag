# 基于大模型与 RAG 的高校课程知识库智能问答系统

# 中期报告（修订稿）

## 二、项目简介

高校课程资料分散于讲义、课件和参考文档，学生查找可靠依据成本较高，通用大模型也可能给出缺少来源或偏离课程范围的回答；教师则难以从日常提问中系统把握共性疑问与资料缺口。本项目建设面向高校课程的知识库智能问答与教学反馈系统，服务学生、教师和课程管理员三类角色。

系统基于 Python/FastAPI、Vue 3、PostgreSQL/pgvector，形成从资料建设到有据问答、再至教学反馈的闭环：支持多格式课程资料解析、质量诊断与可追溯索引；在课程授权范围内开展关键词与向量混合检索，并在证据约束下生成回答与引用溯源，为学生提供可核对问答及依据不足提示；为管理员提供课程、学期组织、成员权限与资料生命周期管理；为教师提供资料管理、问答反馈汇总，以及可选的课问答分析与备课辅助（教师以自然语言了解本课学生提问重点并获取备课参考，输出可核对、经人审阅）。项目强调课程级访问隔离、资料两步启用与运行可诊断、效果可评测，目标交付可本地运行、可演示、可核验的高校课程知识库智能问答系统。

## 三、研究主要内容及实施计划

### （一）主要研究内容

项目以教学业务与三角色页面、课程资料治理及有据可查的 RAG 问答为主线，以效果评测与本地可靠运行为保障，并以教师侧可选的课问答分析与备课辅助为附线能力。研究承接原开题的复杂资料检索、多角色隔离和教学反馈方向，结合中期实现与师生使用场景优化优先级：优先把业务流程、角色界面、演示路径和检索问答做扎实，再在证据可核、边界明确的前提下适度建设教师侧辅助能力。下文分别说明各项研究内容。

1. **多格式课程资料治理与可追溯索引。** 面向 PDF、PPTX、DOCX、Markdown 和纯文本等资料，研究解析、结构化切分、来源元数据保留、质量诊断与索引更新，建立从原始文件到检索片段及引用位置的可追溯链路。针对扫描页、图片文字、公式和图表，将结合代表性样本评估 OCR、视觉等成熟组件的适用性，并以页面覆盖检查和问答效果验证资料处理质量。

2. **课程约束下的混合检索与证据筛选。** 在课程授权范围内结合向量检索（Dense）与关键词检索，研究候选召回、排名融合、证据准入阈值和可选重排的适用条件。以可解释的基础检索作为对照，通过固定题集分别评价候选召回、答案要点、引用支持、严格来源定位、响应耗时和调用成本，并依据实测收益与运行代价确定检索策略。

3. **证据约束生成与引用核验。** 研究检索证据组织、来源信息保留、回答与引用关联及依据不足处理，建立从问题、候选证据到答案和原文位置的核验路径。评价时分别考察事实要点正确性、引用支持、严格页码命中、正确拒答和系统失败，全面呈现答案质量与来源定位情况。

4. **教学业务模型、三角色页面与课程权限。** 在用户、课程、课程成员和资料管理基础上，建设学期、班级、学生名单导入、个人主页（学生学号与所属班级、教师工号等按角色区分）及课程成员关系等基础业务能力，明确管理员、教师和学生各自能够查看与操作的范围，完善三角色界面与演示路径。同步保证资料上传、处理失败、替换、删除、重新索引及资料两步启用检索后的状态一致；教师与管理员之间必要的资料协作流程随业务一并落地。

5. **课程反馈与效果评测。** 教师端提供问答汇总、高频问句等反馈线索，便于发现常见疑问；视需要补充主题分组、人工复核和处理记录，服务日常教学改进。围绕固定题集分别评价检索候选、最终证据、事实支持、引用定位、拒答和系统失败。涉及学生个人掌握程度、成绩或教学质量的判断，仍须独立学习结果和教师审核支持，系统不作替代性评定。

6. **本地运行与交互可靠性。** 系统具备本地运行基础和服务端事件（SSE）流式问答能力；持续验证启动、数据库初始化与迁移、关键业务操作，以及流式事件顺序、取消、超时和异常终态等使用场景，保障演示与日常使用稳定可复现。

7. **教师侧课问答分析与备课辅助（可选、降级）。** 作为附线能力，面向本课教师提供自然语言的学生问答情况分析与备课参考，而非通用调查编排或多 Agent 平台。典型用法包括：询问某份课件相关的学生重点问题，或整理某一时间范围内的问答并给出备课建议。系统消化课内问答日志与相关反馈，减少教师自行翻阅复杂统计表或主观推断掌握度的负担；复用既有课程资料、问答记录与检索证据，采用有限工具与有限步骤，输出结构化、可扫读且尽量可回链到原问句或资料的结果，并由教师审阅后使用。不写入名单、不改权限、不作成绩或个人掌握结论；该能力在业务、页面与 RAG 主线就绪后薄切建设，表述与验收均须边界准确。

项目技术路线可归纳为：以课程权限、资料治理和来源追溯为基础的 RAG 问答主线，辅以区分检索证据与最终答案的分层评测，以及面向教师的可选课问答分析附线。前两项构成中期已验证与结题须持续打磨的核心；教学业务、三角色页面完善与演示质量优先推进，教师侧辅助能力在主线扎实后再按上述边界建设。

与原开题方案相比，项目依据可运行代码、实验结果、指导意见和资源条件优化了技术选型与实施重点：由原计划中的 MySQL、Chroma/Milvus、LlamaIndex、DeepSeek-V4 等组合，调整为当前实际使用的 PostgreSQL/pgvector、模块化检索链路及 DeepSeek deepseek-flash。结题阶段优先完善教学业务、三角色页面与演示体验，持续提升课程 RAG 的证据质量与回答效果；教师侧课问答分析作为可选附线，须说明准确、边界清楚。复杂资料解析、重排、主题分组等增强功能将根据实际问题和对照结果选择。

### （二）实施进度安排

**前期准备与基础建设阶段**，重点开展文献调研、需求分析与架构设计，并搭建前后端和数据库。目前已形成系统架构与本机开发环境，建立课程、成员、资料及问答等基础业务能力。

**核心功能实现阶段**，重点推进资料处理、检索增强问答、引用与多角色功能。目前已形成课程资料入库、课程范围内问答、引用摘录与原 PDF 定位、依据不足提示和基础教师反馈的可演示闭环。

**中期联调与验证阶段**，重点完成系统联调、检索优化、功能测试及汇报准备。目前已建立中文四课演示基线，完成 22 题 Dense/Hybrid 真实模型对照及开发者核验；核心演示路径已完成复核。下一阶段将邀请未参与开发的人员复核代表题目，进一步补充独立评价证据。

**后期一**聚焦教学业务、三角色页面与本地使用流程，完善学期、班级、学生名单、个人主页及课程成员权限等基础业务，梳理管理员、教师和学生的核心操作路径，完成常用操作、权限验证与演示打磨。

**后期二**在业务与 RAG 主线持续完善的前提下，薄切建设教师侧课问答分析与备课辅助（可选附线）。复用现有课程资料、问答记录和检索证据，支持教师以自然语言了解学生提问重点并获取备课参考；输出须可核对、经人审，不以 Agent 替代业务流程或权限决策。

**后期三**聚焦 RAG 质量与系统可靠性，改进证据质量、引用定位与异常处理，并开展效果评测。计划分析资料覆盖、候选准入、页码映射及个别应答失败；补充独立核验和回归测试，验证现有 SSE 流式交互及本地启动、迁移和数据管理。

**结题整理阶段**，汇总成果、测试记录、已知限制与结题材料。计划交付本地运行说明、核心业务与问答使用说明、测试和评测记录及结题材料；教师侧辅助能力若纳入演示，须附边界说明；重排、复杂资料解析和其他增强功能根据实际收益决定是否纳入。

实施顺序上，优先完善课程组织、角色页面、演示路径与 RAG 证据质量；教师侧课问答分析作为附线，在主线就绪后建设。重排、复杂资料解析和主题分组等增强功能将根据代表样本、对照结果与维护成本决定是否纳入。

## 四、项目实施进展

### （一）已开展的工作

1. **完成系统架构与基础业务能力建设。** 基于 Python/FastAPI、Vue 3 和 PostgreSQL/pgvector 建立本机运行的应用原型，当前数据模型覆盖用户、会话、课程、课程成员、资料、入库任务、文本切片、问答日志和洞察复核记录等基础对象，支撑课程级访问控制、检索实验与资料管理。系统建设重心为教学业务、三角色页面与 RAG 问答。

2. **实现资料处理与来源定位链路。** 当前代码支持 PDF、PPTX、DOCX、Markdown 和纯文本等资料的上传、解析、切分及索引。问答流程能够在课程范围内检索资料，生成回答并提供引用摘录及原 PDF 页码入口。中期演示基线为中文四门课程、27 份 PDF、2,501 个文本切片。

3. **建立课程权限与异常状态区分机制。** 已实现课程成员权限相关流程，演示验证了无权限访问路径；系统能够区分依据不足与系统故障，并对存在覆盖警告的资料显示“部分页面需核对”提示。当前有 20 份演示 PDF 带有资料覆盖不完整（COVERAGE_INCOMPLETE）警告。中期演示的核心问答路径已完成复核，权限拒绝和系统故障路径另有截图及日志证据。

4. **形成面向教师的基础问答反馈能力。** 当前教师端提供课程资料管理、成员管理以及问答反馈汇总和高频问句查看，可为教师发现常见疑问提供初步线索。后端已具备实验性的问句分组与复核记录接口。

5. **开展真实模型检索对照与分层核验。** 基于当前中文四门课程的演示数据，对 22 道题分别执行 Dense 与 Hybrid 真实模型测试，并由开发者按既定规则核验。采用分层指标分别记录事实要点、引用支持、严格预期页命中与明显课外问题拒答，呈现不同类型的系统表现。从当前题集结果看，Dense 与 Hybrid 均能完成大部分应答任务，Hybrid 在事实要点指标上略有提升；两种方式的引用支持和严格预期页命中结果一致。拒答测试覆盖了 5 道明显课外问题，结果均符合预期。

6. **完成问答交互与流式返回基础能力。** 学生端能够显示等待状态、区分依据不足与系统错误，并对失败问题提供重试入口；当前问答链路已支持流式返回。

### （二）项目实施存在的困难及解决办法

1. **部分课程资料仍存在覆盖风险。** 当前 27 份演示 PDF 中有 20 份带有 COVERAGE_INCOMPLETE 资料级警告，纯图像/矢量页面、图内文字和部分公式可能无法由原生文本提取完整覆盖。后续将结合代表页面核查解析与切分问题，再评估 OCR 或视觉处理等增强方式，并通过页面前后对照验证效果。

2. **检索策略与引用定位仍有优化空间。** 当前 Dense 与 Hybrid 的整体评测结果接近，后续将结合代表性问题进一步校准证据筛选与融合策略，检查引用定位情况，并通过回归测试验证调整效果。

3. **现有评测独立性有限，演示与回归验证仍须加强。** 当前 22 题结果由开发者核验，属于阶段性自证证据，尚不能等同于未参与开发人员的独立评测。后续将邀请未参与开发的人员复核代表题目，完善核心演示路径与关键业务的回归检查，使效果结论更可对外说明。若建设教师侧课问答分析等辅助能力，将另以小样本任务说明边界与可用性，不将其与 RAG 主线评测混为一谈。

4. **教学业务模型与关键操作可靠性仍需完善。** 中期时点下，学期、班级、学生名单和个人主页等业务对象及三角色页面仍须在结题阶段补齐并打磨演示；新增业务需进一步明确角色权限与课程成员关系。同时，资料替换、删除、失败重试，以及 SSE 流式交互中的取消、超时和异常终态仍需回归验证。后续将补齐必要的业务关系与权限检查，并通过可复现的本地测试核对资料状态、数据库迁移和常用操作。

**靳梓熠**担任前端开发负责人，原定职责为 Vue 3 页面、问答交互、管理界面与可视化。本阶段配合中期演示梳理学生问答与依据核对相关界面路径；参与中期汇报 PPT、讲稿与答辩材料整理，保障演示路径可讲、可操作。下一阶段将重点完善教师、学生和管理员页面与演示体验；若纳入课问答分析辅助，再支持结果查看与人工复核界面。

上述分工与开题人员安排一致。中期已形成可演示的问答与引用核对能力，以及配套汇报答辩材料；后续按上述分工优先推进业务、页面、演示与 RAG，结题相关工作据此展开。
