# 基于大模型与 RAG 的高校课程知识库智能问答系统

# 中期报告（修订稿）

## 二、项目简介

高校课程资料分散于讲义、课件和参考文档，学生查找可靠依据成本较高，通用大模型也可能给出缺少来源或偏离课程范围的回答；教师则难以从日常提问中发现共性疑问与资料缺口。本项目拟建设面向高校课程的知识库智能问答与教学反馈系统，服务学生、教师和课程管理员。系统基于 Python/FastAPI、Vue 3、PostgreSQL/pgvector，结合多格式资料处理、关键词与向量混合检索、证据约束生成和引用溯源，为学生提供可核对问答及依据不足提示，为教师提供资料质量检查、课程问题分析、知识点核验和处理反馈，为管理员提供课程、成员及权限管理。项目强调课程级访问隔离、资料生命周期治理、运行可诊断和效果可评测，目标形成从资料建设、证据问答到教师核查和持续改进的闭环。

## 三、研究主要内容及实施计划

### （一）主要研究内容

项目以高校课程知识库为基础，以有据可查的课程问答为核心用户路径，以教师可核验的课程级反馈为延伸闭环，围绕课程资料质量、答案证据支持、课程权限治理与反馈效果验证开展应用研究和系统开发。研究承接原开题的复杂资料检索、多角色隔离、学情分析和异步流式性能优化方向，并依据当前代码、实验结果与资源条件持续完善技术路线，具体包括以下六方面。

1. **多格式课程资料治理与可追溯索引。** 面向 PDF、PPTX、DOCX、Markdown 和纯文本等资料，研究解析、结构化切分、来源元数据保留、质量诊断与索引更新，建立从原始文件到检索片段及引用位置的可追溯链路。针对扫描页、图片文字、公式和图表，将结合代表性样本评估 OCR、视觉等成熟组件的适用性，并以页面覆盖检查和问答效果验证资料处理质量。

2. **课程约束下的混合检索与证据筛选。** 在课程授权范围内结合向量检索（Dense）与关键词检索，研究候选召回、排名融合、证据准入阈值和可选重排的适用条件。以可解释的基础检索作为对照，通过固定题集分别评价候选召回、答案要点、引用支持、严格来源定位、响应耗时和调用成本，并依据实测收益与运行代价确定检索策略。

3. **证据约束生成与引用核验。** 研究检索证据组织、来源信息保留、回答与引用关联及依据不足处理，建立从问题、候选证据到答案和原文位置的核验路径。评价时分别考察事实要点正确性、引用支持、严格页码命中、正确拒答和系统失败，全面呈现答案质量与来源定位情况。

4. **多角色访问控制与资料生命周期可靠性。** 面向学生、教师和管理员建立职责清晰的业务流程，验证课程授权在资料列表、检索、问答、引用和原文件访问等入口的一致执行；围绕上传、处理失败、重试、替换、删除和重新索引，核对业务记录、原文件、文本切片、向量及引用状态。通过权限矩阵、重复操作和异常恢复测试，降低跨课程访问及数据状态不一致风险。

5. **课程级学情分析与教师反馈闭环。** 承接原开题提出的提问去噪、语义聚类、核心问题归纳和教师看板方向，将问答日志转化为可供教师核查的课程级学习需求线索。后续比较 Embedding 分组、规则标签及经授权的 LLM 辅助主题归纳；以人工标注评估误合并、误拆分和未覆盖问题，并把教师确认的主题/知识点、回答结果分布、处理动作与代表问题回归连接起来。当前已具备描述性统计和待核查线索，下一阶段将完善主题确认与处理回归闭环；涉及个人掌握程度、成绩或教学质量的分析，将结合测验、作业等独立学习结果及教师审核开展。

6. **异步流式交互与运行性能评价。** 延续原开题关于 FastAPI 异步处理、前端 EventSource/流式输出及低延迟、高并发的研究方向。后续先建立当前请求—响应链路的性能基线，再验证流式事件顺序、取消、超时清理、异常终态和并发隔离；在可复现负载下记录首事件延迟、端到端耗时、吞吐与错误率，并分别报告 Fake 和真实模型测试结果。进一步优化将综合评估实际收益、运行成本和维护复杂度。

项目特色体现在高校课程场景下的系统性设计：一是构建“问题—课程证据—回答—引用位置”的可核对链路，并用分层指标评价事实、引用和定位质量；二是将课程权限贯穿检索、问答、引用和原文件访问，并关注资料替换、删除、重试后的状态一致性；三是将教师学情分析设计为“问题归纳—人工核查—处理记录—代表问题回归”的人机协同闭环；四是以固定题集、失败样本和可复现测试支撑技术方案选择。上述设计将课程证据、权限治理、人机协同和效果评测结合起来，形成面向真实教学业务的系统化工程方案。

**开源设计借鉴与工程化取舍。** 项目方案参考了相关开源产品和公开设计：从 [RAGFlow](https://github.com/infiniflow/ragflow) 研究文档解析、处理状态与质量治理，从 [Kotaemon](https://github.com/Cinnamon/kotaemon) 研究文档问答中的证据展示与引用核对，从 [Moodle Learning Analytics](https://moodledev.io/docs/5.0/apis/subsystems/analytics) 借鉴“指标—分析—洞察—行动”的教学反馈思路，并参考 [Arize Phoenix](https://github.com/Arize-ai/phoenix) 的追踪与实验评测理念，以及 [Jisc 学习分析规范](https://www.jisc.ac.uk/guides/code-of-practice-for-learning-analytics) 对透明性、数据最小化和人工监督的要求。本阶段重点开展公开设计调研与课程场景适配，后续将结合具体需求评估成熟组件的复用价值，综合考察版本、许可证、传递依赖、集成成本和维护收益，优先选择适配性强、可持续维护的能力模块。

与原开题方案相比，项目依据可运行代码、实验结果和资源条件优化了技术选型与实施顺序：由原计划中的 MySQL、Chroma/Milvus、LlamaIndex、DeepSeek-V4 等组合，调整为当前实际使用的 PostgreSQL/pgvector、模块化检索链路及 DeepSeek deepseek-flash。复杂检索、语义分析和性能研究将通过固定题集、人工标注和性能测量持续验证。结题阶段优先完善资料与权限可靠性、教师学情分析闭环、独立评价和可复现交付；重排、复杂资料解析及其他增强功能将结合质量收益、成本、隐私和维护要求逐项评估。

## 四、项目实施进展

### （一）已开展的工作

1. **完成系统架构与产品工程方案梳理。** 基于 Python/FastAPI、Vue 3 和 PostgreSQL/pgvector 建立本机运行的应用原型，形成课程、成员、资料和问答等基础业务模型，为课程级访问控制、检索实验和数据管理提供统一基础。同时围绕文档生命周期、引用核对、教师分析闭环、运行追踪与效果评测，对成熟开源方案的公开设计开展初步调研，并沉淀结题产品定义、验收标准和任务清单，为后续功能完善与工程化验收提供依据。

2. **实现资料处理与来源定位链路。** 当前代码支持 PDF、PPTX、DOCX、Markdown 和纯文本等资料的上传、解析、切分及索引；本次中期真实数据基线以 PDF 为主，其他格式的专项效果将在后续补充验证。问答流程能够在课程范围内检索资料，生成回答并提供引用摘录及原 PDF 页码入口。正式演示基线为中文四门课程、27 份 PDF、2,501 个文本切片。

3. **建立课程权限与异常状态区分机制。** 已实现课程成员权限相关流程，演示验证了无权限访问路径；系统能够区分依据不足与系统故障，并对存在覆盖警告的资料显示“部分页面需核对”提示。当前 COVERAGE_INCOMPLETE 为资料级质量警告，27 份资料中有 20 份带此警告；页级 empty/sparse/abnormal 明细将作为后续改进项，逐步建设可查询的页面级诊断能力。中期演示的核心问答路径已完成复核与彩排，权限拒绝和系统故障路径另有截图及日志证据，后续将结合更多课程资料和异常场景扩展验收范围。

4. **形成面向教师的基础描述性反馈能力。** 教师侧可查看课程问答统计、依据不足问题列表及资料处理状态，为核对重复问题和潜在资料缺口提供线索；项目还保留了实验性的相似问句分组能力。下一阶段将校准分组阈值，通过人工标注验证主题/知识点归纳质量，并完善“教师核查—处理记录—改进后回归”的闭环。涉及学生个人掌握程度、成绩或教师教学质量的分析，将结合测验、作业等独立学习结果和教师审核开展。

5. **开展真实模型检索对照与分层核验。** 在 univ_course_rag_cn_v2 上，对 22 道题分别执行 Dense 与 Hybrid 真实模型测试，并由开发者按既定规则核验。采用分层指标分别记录事实要点、引用支持、严格预期页命中与明显课外问题拒答，呈现不同类型的系统表现。主要结果如下：
   
   | 评价指标                           | Dense | Hybrid |
   | ------------------------------ | -----:| ------:|
   | 全部应答题中的事实要点通过率（17 题为分母，未回答计失败） | 15/17 | 16/17  |
   | 已回答应答题中的事实要点通过率                | 15/16 | 16/16  |
   | 已回答应答题中的引用支持通过率                | 16/16 | 16/16  |
   | 严格预期页命中                        | 12/16 | 12/16  |
   | 明显课外问题的正确拒答                    | 5/5   | 5/5    |
   
   本轮核验由项目开发者完成，后续将邀请未参与开发的人员复核代表题目，并继续保持各项指标分层呈现。严格预期页命中与引用支持分别反映来源定位和内容支持情况；5/5 的拒答结果覆盖明显课外问题。当前余弦分数门槛 0.45 将继续校准，Rerank 将结合校准结果开展评估；Hybrid 本轮召回了关键词独有候选，但 431 个 Keyword-only 候选均未进入最终 evidence，后续将重点检查证据准入阈值与融合策略，以判断其对最终答案质量的实际贡献。此外，本轮 Hybrid runner 为诊断候选层额外执行了一次检索，latency_ms 和 Embedding 调用量包含额外诊断开销；后续将采用统一 runner 和测量口径开展性能对照。

6. **完成问答等待、失败提示与重试等交互处理。** 学生端能够显示等待状态、区分依据不足与系统错误，并对失败问题提供重试入口。当前问答 API 采用完整请求—响应方式返回结果，EventSource 逐段流式输出、标准化并发压力测试和性能基线将作为后续工程任务推进，以数据验证原开题提出的低延迟、高并发优化目标。

### （二）项目实施存在的困难及解决办法

1. **部分资料仍存在覆盖警告，页级诊断有待完善。** 当前 27 份演示 PDF 中有 20 份带 COVERAGE_INCOMPLETE 资料级警告，该指标反映需要进一步核查的资料覆盖风险。纯图像/矢量页面、图内文字及部分公式仍可能无法由原生文本路径完整提取；页级 empty/sparse/abnormal 诊断将进一步整理为教师可查询的页面级信息。后续将依据固定代表页定位具体缺口，分析解析与切分环节，并评估 OCR/视觉等专项增强，通过代表页面前后对照验证改进效果。
2. **Hybrid 的增益仍需进一步评估。** 当前实现能够召回关键词独有候选，但本轮 431 个 Keyword-only 候选均未进入最终 evidence，显示现有 cosine 分数门槛 0.45 与证据准入策略仍有校准空间，Rerank 也有待评估。后续将记录各检索分支的候选、排名和过滤原因，在同一题集上校准门槛并比较检索召回、答案质量与运行代价，再根据结果决定是否引入重排。本轮 Hybrid runner 含诊断重复检索，后续性能比较将采用统一 runner 和测量口径。
3. **引用支持与严格页码命中存在差异。** 已回答题的引用支持核验为 16/16，严格预期页命中为 12/16。初步记录显示，合并切片的页码记录方式与题集标注的 PDF 页序可能存在口径差异，后续将结合原 PDF、切片来源元数据和前端页码定位开展复核，区分页码映射问题与内容支持问题；修复后使用代表题目回归核验，并保留原始页面作为人工复查依据。
4. **个别应答题仍会返回依据不足。** PROB-F02 属于预期应回答的问题，Dense 与 Hybrid 本轮均未给出答案。后续将按资料覆盖、候选召回、过滤结果、模型上下文和生成状态的顺序检查记录，定位资料缺口、检索遗漏、门槛设置或生成环节的影响；再针对根因调整对应环节，并以修复前后及相邻代表题目的回归结果验证改进效果。
5. **评价的独立性、学情分析质量和用户体验仍需补充验证。** 当前 22 题结果由开发者核验，题量和任务覆盖属于阶段性验证范围；相似问句分组也有待独立人工标注评价。后续将冻结包含预期答案要点和来源标注的题集，计划扩充至约 60–80 题，并邀请未参与开发的人员复核代表题目；同时为问句分组/主题标签建立人工标注集，报告误合并、误拆分、覆盖率和教师修正情况。另安排小规模学生/教师任务试用，记录任务完成、引用核对、主要困惑和失败点，综合形成独立核验、学情分析评价与用户体验的多维证据。
6. **资料生命周期、开源复用与最终交付需要系统验证。** 后续将重点验证资料替换、删除、失败重试和异常中断后的状态一致性，检查原文件、数据库记录、文本切片和向量索引的联动结果；同时在干净环境复核安装、数据库迁移、启动与恢复流程。开源方面，现阶段已开展设计思路调研，后续将围绕拟复用模块核对项目版本、许可证、传递依赖、必要声明和集成成本，并检查课程资料公开范围与密钥配置。最终验收将综合参考可重复测试记录、许可证核对结果和环境恢复表现。
7. **异步流式与高并发优化需要开展专项验证。** 当前问答 API 以完整请求—响应方式返回，EventSource 流式输出和标准化并发压力测试列入后续工程任务。后续将在统一环境下测量现有链路的端到端延迟、错误率与吞吐，再完成流式响应及相关异常处理，并测试首事件延迟、取消、超时、终态处理和并发隔离；Fake 与真实模型结果将分别记录，为性能优化和部署配置提供依据。
