# 基于大模型与 RAG 的高校课程知识库智能问答系统

# 中期报告（修订稿）

## 二、项目简介

高校课程资料分散于讲义、课件和参考文档，学生查找可靠依据成本较高，通用大模型也可能给出缺少来源或偏离课程范围的回答；教师则难以从日常提问中系统把握共性疑问与资料缺口。本项目建设面向高校课程的知识库智能问答与教学反馈系统，服务学生、教师和课程管理员三类角色。

系统基于 Python/FastAPI、Vue 3、PostgreSQL/pgvector，建设课程资料管理、知识库检索问答与教学反馈相结合的应用平台。管理员负责课程组织、成员权限及资料管理，教师可建设课程知识库、查看学生问答反馈，学生可在授权课程内提问并查看回答依据及原文位置。项目将持续完善多格式资料解析、混合检索、结果重排、引用溯源和三角色操作流程，并在此基础上建设轻量级教师侧问答分析助手，辅助教师整理常见问题和备课参考。最终形成业务流程完整、权限清晰、问答可靠、可本地运行和演示的高校课程知识库系统。

## 三、研究主要内容及实施计划

### （一）主要研究内容

项目围绕课程业务管理、三角色页面、课程知识库建设与 RAG 问答展开，重点完善从课程资料上传、处理和启用，到学生问答、引用核对和教师反馈的完整流程。结合中期进展与指导意见，后续工作首先保障基础业务、权限控制、知识库质量和演示体验，在此基础上建设教师侧轻量级分析助手。

1. **多格式课程资料治理与可追溯索引。** 面向 PDF、PPTX、DOCX、Markdown 和纯文本等资料，完善解析、结构化切分、来源信息保留、质量诊断和索引更新，建立从原始文件到检索片段及引用位置的可追溯链路。针对扫描页、图片文字、公式和图表，补充成熟 OCR 识别、重点内容核对和必要的人工补录，提高课程资料的可检索范围与引用准确性。

2. **课程约束下的混合检索与证据筛选。** 在课程授权范围内结合向量检索（Dense）与关键词检索，完善候选召回、融合排序和证据筛选，并引入检索重排以提高资料匹配质量。通过固定题集对检索结果、答案要点、引用支持、来源定位、响应耗时和调用成本进行对照测试，持续优化问答效果。

3. **证据约束生成与引用核验。** 研究检索证据组织、来源信息保留、回答与引用关联及依据不足处理，建立从问题、候选证据到答案和原文位置的核验路径。评价时分别考察事实要点正确性、引用支持、严格页码命中、正确拒答和系统失败，全面呈现答案质量与来源定位情况。

4. **教学业务模型、三角色页面与课程权限。** 在用户、课程、课程成员和资料管理基础上，建设学期、班级、学生名单导入、个人主页（学生学号与所属班级、教师工号等按角色区分）及课程成员关系等基础业务能力，明确管理员、教师和学生各自能够查看与操作的范围，完善三角色界面与演示路径。同步保证资料上传、处理失败、替换、删除、重新索引及资料两步启用检索后的状态一致；教师与管理员之间必要的资料协作流程随业务一并落地。

5. **课程反馈与效果评测。** 完善教师端问答汇总、高频问题、主题分组和反馈复核等功能，帮助教师发现课程中的常见疑问。围绕固定题集开展检索、回答质量、引用定位、拒答和异常处理测试，为知识库优化和教学使用提供依据。

6. **本地运行与交互可靠性。** 系统具备本地运行基础和服务端事件（SSE）流式问答能力；持续验证启动、数据库初始化与迁移、关键业务操作，以及流式事件顺序、取消、超时和异常终态等使用场景，保障演示与日常使用稳定可复现。

7. **教师侧课程问答分析 Agent。** 在已有教师反馈和课程知识库基础上，建设轻量级教学分析助手。教师选择课程与时间范围后，可通过自然语言汇总学生常见问题、查找相关课件，并生成备课参考。系统通过受控流程调用已有问答记录和 RAG 检索功能，分析结果附原始问句与课件依据，供教师核对使用。该功能在基础业务和问答链路完善后实施，并通过典型任务验证。

项目技术路线以课程与权限管理、资料治理、RAG 问答及引用溯源、教师反馈为主体，通过功能测试和问答评测保障实际使用效果。教师侧分析助手直接复用上述业务数据与检索能力，作为课程知识库的辅助应用场景。

与原开题方案相比，项目根据中期实现与实际教学需求调整了技术选型，由原计划的 MySQL、Chroma/Milvus、LlamaIndex 等组合，优化为 PostgreSQL/pgvector 与模块化 RAG 链路，并接入大模型服务。结题阶段重点推进学期、班级、课程成员等业务建设，完善三角色页面与权限管理，同时加强资料解析、检索重排、证据筛选和引用定位，提升知识库质量与演示体验。

### （二）实施进度安排

**前期准备与基础建设阶段**，重点开展文献调研、需求分析与架构设计，并搭建前后端和数据库。目前已形成系统架构与本机开发环境，建立课程、成员、资料及问答等基础业务能力。

**核心功能实现阶段**，重点推进资料处理、检索增强问答、引用与多角色功能。目前已形成课程资料入库、课程范围内问答、引用摘录与原 PDF 定位、依据不足提示和基础教师反馈的可演示闭环。

**中期联调与验证阶段**，重点完成系统联调、检索优化、功能测试及汇报准备。目前已建立中文四课演示基线，完成 22 题 Dense/Hybrid 真实模型对照及开发者核验；核心演示路径已完成复核。

**后期一**完善教学业务和三角色页面，补齐学期、班级、学生名单、个人主页及课程成员关系等基础功能，进一步落实课程权限和资料管理流程。围绕管理员课程管理、教师资料与反馈管理、学生授权问答和引用回跳，打磨完整、流畅的操作与演示路径。

**后期二**重点提升课程知识库与 RAG 问答质量。完善资料解析和页面覆盖检查，对扫描页、图表文字补充识别与核对；优化混合检索、结果重排、证据筛选和引用定位，同时完善资料更新、失败重试及流式问答的交互体验。

**后期三**在核心业务和 RAG 链路完善的基础上，实现教师侧课程问答分析助手，完成常见问题归纳、课件关联与备课参考展示。同步开展三角色业务回归、权限测试、RAG 分层评测和教师侧典型任务测试，重点核对数据来源、引用结果和异常处理。

**结题整理阶段**，完成系统联调和现场演示准备，汇总运行说明、核心功能说明、测试与评测记录及结题材料。演示以课程管理、三角色操作、知识库问答及引用核对为主体，并展示教师反馈和辅助分析成果，形成完整的教学应用流程。

实施过程中，优先保障课程业务、角色权限、知识库质量和问答演示的完整性，再扩展教师侧辅助功能，各阶段均通过可复现的功能测试和效果核验保证交付质量。

## 四、项目实施进展

### （一）已开展的工作

1. **完成系统架构与基础业务能力建设。** 基于 Python/FastAPI、Vue 3 和 PostgreSQL/pgvector 建立本机运行的应用原型，当前数据模型覆盖用户、会话、课程、课程成员、资料、入库任务、文本切片、问答日志和洞察复核记录等基础对象，支撑课程级访问控制、检索实验与资料管理。系统建设重心为教学业务、三角色页面与 RAG 问答。

2. **实现资料处理与来源定位链路。** 当前代码支持 PDF、PPTX、DOCX、Markdown 和纯文本等资料的上传、解析、切分及索引。问答流程能够在课程范围内检索资料，生成回答并提供引用摘录及原 PDF 页码入口。中期演示基线为中文四门课程、27 份 PDF、2,501 个文本切片。

3. **建立课程权限与异常状态区分机制。** 已实现课程成员权限相关流程，演示验证了无权限访问路径；系统能够区分依据不足与系统故障，并对存在覆盖警告的资料显示“部分页面需核对”提示。当前有部分演示 PDF 带有资料覆盖不完整警告。中期演示的核心问答路径已完成复核，权限拒绝和系统故障路径另有截图及日志证据。

4. **形成面向教师的基础问答反馈能力。** 当前教师端提供课程资料管理、成员管理、问答反馈汇总和高频问句查看，帮助教师了解课程中的常见疑问；后端已具备实验性的问句分组和复核记录接口，为后续完善教学反馈和辅助分析功能奠定基础。

5. **开展真实模型检索对照与分层核验。** 基于当前中文四门课程的演示数据，对 22 道题分别执行 Dense 与 Hybrid 真实模型测试，并由开发者按既定规则核验。采用分层指标分别记录事实要点、引用支持、严格预期页命中与明显课外问题拒答，呈现不同类型的系统表现。从当前题集结果看，Dense 与 Hybrid 均能完成大部分应答任务，Hybrid 在事实要点指标上略有提升；两种方式的引用支持和严格预期页命中结果一致。拒答测试覆盖了 5 道明显课外问题，结果均符合预期。

6. **完成问答交互与流式返回基础能力。** 学生端能够显示等待状态、区分依据不足与系统错误，并对失败问题提供重试入口；当前问答链路已支持流式返回。

### （二）项目实施存在的困难及解决办法

1. **部分 PDF 页面文字提取不完整，影响问答依据。** 当前 27 份演示 PDF 中有 20 份在入库时提示部分页面未能完整提取文字，多为扫描页、纯图页、图内文字或公式页。这类页面进入知识库的文本可能不全，对应内容的问答可能缺依据或页码定位不准。后续将补充重点页面 OCR 识别与人工核对，完善解析质量检查和页面内容补录，并通过问答测试验证改进效果。

2. **检索策略与引用定位仍有优化空间。** 当前 Dense 与 Hybrid 的整体评测结果接近。后续将完善召回融合与证据筛选，引入重排环节，核对引用页码及原文位置，通过固定题集和回归测试持续改进问答质量。

3. **教学业务模型与关键操作可靠性仍需完善。** 中期时点下，学期、班级、学生名单和个人主页等业务对象及三角色页面仍须在结题阶段补齐并打磨演示；新增业务需进一步明确角色权限与课程成员关系。同时，资料替换、删除、失败重试，以及 SSE 流式交互中的取消、超时和异常终态仍需回归验证。后续将补齐必要的业务关系与权限检查，并通过可复现的本地测试核对资料状态、数据库迁移和常用操作。
