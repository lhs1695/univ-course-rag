## 1. 项目简介（建议 1～2 页）

### 页：背景与问题

高校课程资料通常分散在讲义、课件和各类参考文档中。学生想核对某个知识点时，往往要在多个文件里翻找，成本高、也难保证找到的是本课指定材料。通用大模型虽然能快速生成回答，但常见两类风险：一是缺少可核对的来源，二是答案可能超出本门课程范围，甚至编造课内并不存在的内容。与此同时，教师日常能接触到学生提问，却缺少系统化手段，从一批问答里归纳共性疑问、发现资料缺口，并据此调整备课。

因此，本项目面向真实教学场景，建设「课程知识库智能问答 + 教学反馈」系统，服务学生、教师和课程管理员三类角色，强调**课内可控、回答有依据、可回到原文核对**。

### 页：建设目标与角色

系统基于 Python/FastAPI、Vue 3、PostgreSQL/pgvector，将课程资料管理、知识库检索问答与教学反馈结合为可本地运行的应用平台。

- **管理员**：负责课程组织、成员权限与资料管理，控制哪些资料进入检索。  
- **教师**：建设与维护课程知识库，查看学生问答反馈，把握高频疑问。  
- **学生**：在授权课程内提问，查看回答依据，并可通过引用回到原文位置核对。  

项目将持续完善多格式资料解析、混合检索、结果重排、引用溯源和三角色操作流程。在业务与 RAG 主线稳定后，再建设轻量级教师侧问答分析助手，辅助整理常见问题与备课参考。最终目标是形成业务流程完整、权限清晰、问答可靠、便于本机演示的高校课程知识库系统。**答辩时不要把「教师分析助手」说成已经上线的通用 Agent 平台。**

### 页：技术路线（口述短版）

前后端分离：Vue 3 负责三角色界面；FastAPI 负责权限、资料入库、检索与生成；PostgreSQL + pgvector 存业务数据与向量索引。Embedding 使用硅基流动 BGE-M3，回答生成使用 DeepSeek。演示默认以课内 Dense 检索为主；Hybrid 等策略可用于对照，不作中期「必须显著更优」的结论。

## 2. 研究主要内容（建议 2 页）

### 页：研究内容总述

项目围绕**课程业务管理、三角色页面、课程知识库建设与 RAG 问答**展开，重点打通从资料上传、处理、启用检索，到学生问答、引用核对和教师反馈的完整流程。结合中期进展与指导意见，后续工作首先保障基础业务、权限控制、知识库质量和演示体验，再在此基础上建设教师侧轻量级分析助手。

技术路线以课程与权限管理、资料治理、RAG 问答及引用溯源、教师反馈为主体，通过功能测试和问答评测保障实际使用效果。教师侧分析助手直接复用上述业务数据与检索能力，作为辅助应用场景，而不是另起一套知识库。

### 页：七项研究内容（可拆成两页）

**1. 多格式课程资料治理与可追溯索引**  
面向 PDF、PPTX、DOCX、Markdown 和纯文本等资料，完善解析、结构化切分、来源信息保留、质量诊断和索引更新，建立从原始文件到检索片段及引用位置的可追溯链路。针对扫描页、图片文字、公式和图表，补充成熟 OCR、重点内容核对和必要的人工补录，提高可检索范围与引用准确性。

**2. 课程约束下的混合检索与证据筛选**  
在课程授权范围内结合向量检索（Dense）与关键词检索，完善候选召回、融合排序和证据筛选，并引入检索重排以提高匹配质量。通过固定题集对检索结果、答案要点、引用支持、来源定位、响应耗时和调用成本做对照测试，持续优化问答效果。

**3. 证据约束生成与引用核验**  
研究检索证据组织、来源保留、回答与引用关联，以及依据不足时的处理方式，建立从问题、候选证据到答案和原文位置的核验路径。评价时分别考察事实要点正确性、引用支持、严格页码命中、正确拒答和系统失败，避免用单一「准确率」掩盖不同类型问题。

**4. 教学业务模型、三角色页面与课程权限**  
在用户、课程、课程成员和资料管理基础上，建设学期、班级、学生名单导入、个人主页（学生学号、教师工号等按角色区分）及课程成员关系，明确三类角色各自可查看与操作的范围，完善界面与演示路径。同步保证资料上传、失败、替换、删除、重新索引以及「两步启用检索」后的状态一致。

**5. 课程反馈与效果评测**  
完善教师端问答汇总、高频问题、主题分组和反馈复核等能力，帮助教师发现常见疑问。围绕固定题集开展检索、回答质量、引用定位、拒答和异常处理测试，为知识库优化和教学使用提供依据。

**6. 本地运行与交互可靠性**  
系统具备本地运行基础和服务端事件（SSE）流式问答能力；持续验证启动、数据库初始化与迁移、关键业务操作，以及流式事件顺序、取消、超时和异常终态，保障演示与日常使用稳定可复现。

**7. 教师侧课程问答分析 Agent（附线）**  
在已有教师反馈和课程知识库基础上，建设轻量级教学分析助手。教师选择课程与时间范围后，可用自然语言汇总学生常见问题、查找相关课件并生成备课参考。系统通过受控流程调用已有问答记录和 RAG 检索，结果附原始问句与课件依据，供教师核对。该功能在基础业务和问答链路完善后实施，并通过典型任务验证。

### 页：相对开题的调整（可作半页）

与原开题方案相比，项目根据中期实现与实际教学需求调整了技术选型：由原计划中的 MySQL、Chroma/Milvus、LlamaIndex 等组合，优化为 **PostgreSQL/pgvector 与模块化 RAG 链路**，并接入大模型服务。结题阶段重点仍是学期、班级、课程成员等业务建设，完善三角色页面与权限，同时加强资料解析、检索重排、证据筛选和引用定位，而不是再做框架级推倒重建。

## 4. 项目实施进展（建议 2～3 页）

### 页：已开展工作（上）

**（1）系统架构与基础业务能力**  
基于 Python/FastAPI、Vue 3 和 PostgreSQL/pgvector 建立本机运行的应用原型。当前数据模型覆盖用户、会话、课程、课程成员、资料、入库任务、文本切片、问答日志和洞察复核记录等对象，支撑课程级访问控制、检索实验与资料管理。系统建设重心明确为教学业务、三角色页面与 RAG 问答。

**（2）资料处理与来源定位链路**  
代码支持 PDF、PPTX、DOCX、Markdown 和纯文本的上传、解析、切分及索引。问答流程能在课程范围内检索资料，生成回答并提供引用摘录及原 PDF 页码入口。中期演示基线为中文四门课程、**27 份 PDF、2,501 个文本切片**。

**（3）课程权限与异常状态区分**  
已实现课程成员权限相关流程，演示验证了无权限访问路径。系统能够区分「依据不足」与「系统故障」，并对存在覆盖警告的资料给出「部分页面需核对」类提示。核心问答路径已完成复核；权限拒绝和系统故障路径另有截图及日志证据。

### 页：已开展工作（下）

**（4）面向教师的基础问答反馈**  
教师端提供课程资料管理、成员管理、问答反馈汇总和高频问句查看，帮助了解课程中的常见疑问。后端已具备实验性的问句分组和复核记录接口，为后续完善教学反馈和辅助分析奠定基础。

**（5）真实模型检索对照与分层核验**  
基于四门课程演示数据，对 22 道题分别执行 Dense 与 Hybrid 真实模型测试，并由开发者按既定规则核验。采用分层指标分别记录事实要点、引用支持、严格预期页命中与明显课外问题拒答。从当前题集看，两侧均能完成大部分应答；Hybrid 在事实要点上略有提升；引用支持与严格页命中结果一致；5 道明显课外拒答均符合预期。具体分数见下一节成果表。

**（6）问答交互与流式返回**  
学生端可显示等待状态，区分依据不足与系统错误，并为失败问题提供重试入口；当前问答链路已支持流式返回。

### 页：困难与解决办法

**困难一：部分 PDF 页面文字提取不完整，影响问答依据**  
当前 27 份演示 PDF 中有 20 份在入库时提示部分页面未能完整提取文字，多为扫描页、纯图页、图内文字或公式页。这类页面进入知识库的文本可能不全，对应内容的问答可能缺依据或页码定位不准。  
**对策：** 后续补充重点页面 OCR 识别与人工核对，完善解析质量检查和页面内容补录，并通过问答测试验证改进效果。

**困难二：检索策略与引用定位仍有优化空间**  
当前 Dense 与 Hybrid 的整体评测结果接近。  
**对策：** 完善召回融合与证据筛选，引入重排环节，核对引用页码及原文位置，通过固定题集和回归测试持续改进。

**困难三：教学业务模型与关键操作可靠性仍需完善**  
中期时点下，学期、班级、学生名单和个人主页等业务对象及三角色页面仍须在结题阶段补齐并打磨；资料替换、删除、失败重试，以及 SSE 流式交互中的取消、超时和异常终态仍需回归验证。  
**对策：** 补齐必要的业务关系与权限检查，通过可复现的本地测试核对资料状态、数据库迁移和常用操作。

## 7. 本机怎么开

1. 打开 Docker Desktop，在仓库根执行：`docker compose up -d postgres`  
2. 后端：在 `backend` 使用项目 venv 启动 uvicorn，监听 `http://127.0.0.1:8000`  
3. 前端：在 `frontend` 执行 `npm run dev`，浏览器打开 **[http://127.0.0.1:5173](http://127.0.0.1:5173)**（务必走 Vite，不要直接用 :8000 的登录页）  
4. 本机 `.env` 配置 SiliconFlow（Embedding）与 DeepSeek（生成）；**不要把 Key 写进 PPT、群聊或仓库**

负责人机器若已启动，可直接使用上述地址。换电脑需自备 Docker、库数据、Key，并保证上传目录与库内路径一致。

### 学生（主线，建议必录）

1. 登录学生账号 → 确认课列表四门，前两门为机器学习、智能移动机器人。  
2. 进入一门课的**资料**页：打开 PDF 或 PPTX，确认**页内预览**（可缩放、翻页）；可顺带点「下载」说明仍支持下载。  
3. 进入**问答**：提出课内问题 → 得到回答与依据/引用 → **点击引用**回到原文页（PDF 尽量带页码）。  
4. （可选）提一个明显课外问题 → 应提示依据不足，不编造答案。

### 教师

1. 登录后进入同一门课，展示资料树或上传入口，说明教师可维护课内资料。  
2. 打开**问答反馈**：展示汇总数字与高频问句表即可，不必展开复杂统计口径。

### 管理员

1. 展示课程、成员管理，以及资料「启用检索」（入库成功后再启用的两步流程）。  
2. （可选）扫一眼学院 / 学期等业务页，体现三角色业务能力。

注意：导航中**不应再出现**「课程调查」类调查 Agent 入口（该半成品产品面已撤除；结题若做教师分析助手是另一条附线）。

## 10. 推荐提问（按课）

问句尽量贴近课件标题或目录用语；问得过空可能导致「依据不足」，属于系统按证据约束工作的正常表现，可换一题再录。

### 线性代数（经典对照题）

- **有引用**：`根据线性代数讲义，线性代数主要研究哪两类对象？`  
- **拒答**：`根据线性代数讲义，如何用 SQL 创建数据库表并插入数据？`  
  预期：依据不足，不编造 SQL。

### 机器学习

- `线性模型的基本形式是什么？`  
- `贝叶斯决策的基本思想是什么？`  
- `什么是过拟合？`  
- `回归分析讲了什么？`  

### 智能移动机器人

- `根据课程资料，简述智能移动机器人课程关注的主要内容。`  
- 也可围绕感知、定位、地图构建、路径规划提问。

### 教育学原理

- 打开资料页查看文件名后，按具体讲义内容拟问。  
- 资料应能页内打开；若异常先联系负责人，勿在录屏中长时间卡住。

## 11. 建议 PPT 页序

1. 标题 + 一句话目标  
2. 背景与问题（§1 第一页文案）  
3. 建设目标与三角色（§1 第二页）  
4. 研究内容总述 + 七项（§2，可拆页）  
5. 开题到中期的技术选型调整（半页）  
6. 实施计划时间轴：已完成 / 后期一～三 / 结题（§3）  
7. 已开展工作（§4，可上下两页）  
8. 困难与对策（§4）  
9. 阶段性成果总述 + 数字表（§5）  
10. 系统演示（接学生问答与引用回跳录屏）  
11. 三角色补充（教师反馈、管理员启用）  
12. 后续计划与分工（后期一业务 → 后期二 RAG → 后期三分析助手）  
13. 致谢（可选）  

每页正文可直接从上文对应小节复制后略删句，保持与报告口径一致。

## 12. 不要做的事

- 不要把 `.env`、API Key、真实密码、数据库 dump 放进公开材料或仓库。  
- 不要宣称「准确率百分之多少」；只用分层分数表述。  
- 不要说调查 Agent、多 Agent 或知识图谱已经做成。  
- 不要把当前演示库课表硬说成报告里的 27 份 PDF 清单。  
- 录屏失败时：换课、换问句，或改用成功截图；不要现场大规模重入库或反复改 Key 把环境弄崩。
