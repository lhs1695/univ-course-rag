## 1. 项目定位与副题

本项目要做的不是「随便接一个大模型、让它聊课程」，而是面向**高校课程 PDF 资料**的问答原型：学生在一门具体课程里提问，系统在**该课已授权资料**里检索，再生成带引用的回答，并支持点回原 PDF 页核对。

副题可以记成三句话：**有依据、可核对、能解释失败**。

- **有依据**：回答应建立在课内检索到的证据上，而不是模型的通识流畅编造。
- **可核对**：引用不只是装饰；用户应能打开原文页（URL 含 `#page=`）自己对照。
- **能解释失败**：当依据不足、系统出错、或用户无权限时，界面与语义要分开，不能一律说成「答不上来」或一律说成「坏了」。

封面级预告的四条技术亮点（后文详解）是：

1. 课界权限贯穿检索 / 生成 / 打开原文件；
2. 证据链从页级解析走到原文页；
3. 失败语义四分（有据 / 依据不足 / 系统故障 / 权限拒绝）；
4. 可审计的分层评测与门禁口径。

汇报时务必标明：**v6 是候选稿**；库口径是 **cn_v2：4 / 27 / 2501**。不要在封面上堆栈名，也不要写成「已上生产」或「公网已开放」。

## 2. 痛点、核心叙事问题与中期交付边界

### 2.1 痛点为什么成立

高校一门课往往堆着多份课件、讲义、阅读材料。学生真正的困难通常不是「搜不到文件名」，而是：

1. **资料分散，自然语言问题难定位**  
   学生问的是概念、定义、框架（例如「线性代数主要研究哪两类对象」），而不是「请打开某 PDF 第几页」。靠文件夹和文件名检索，对自然语言提问帮助有限。

2. **通用大模型流畅 ≠ 当前课程口径**  
   大模型可以流利地讲向量空间、概率、管理学概念，但流畅不等于「这句话来自本课讲义、且能指回某一页」。课程教学需要的是**可核对的课内依据**，不是通识百科式的自信回答。

3. **多课并存时必须守边界**  
   同一学生可能选多门课；同一文件名也可能出现在不同课。若未授权课程仍能检索或打开原文，就会造成内容泄漏或串课。因此「能不能问」本身就是产品能力，而不只是检索质量问题。

这三点合在一起，决定了中期叙事不能停在「我们做了 RAG」，而要落到权限、证据链和失败语义上。

### 2.2 核心叙事问题（必须能原样说出）

> **如何让高校课程问答遵守课程边界、提供可核对依据，并在依据不足时正确停止？**

这句话同时约束三件事：课界（谁能用哪些资料）、依据（答从哪来、能否回原文）、停止（不该答时不编造）。后文四个亮点都是在回答这句话。

### 2.3 中期交付边界（说清「做到哪、没做到哪」）

中期能诚实交付的，是**本机文本型原型**：

- 学生：提问 → 看到引用 → 点开原 PDF 页；
- 能把「有据回答 / 依据不足 / 系统故障 / 权限拒绝」分开演示或对照截图说明；
- 有中文四课入库规模与 22 题开发者核验的分层数字可报。

中期**不宣称**：生产可用、公网已上线、通用 OCR / 扫描件完备、可靠公式与复杂图表理解已完成、人工独立评测已完成、阈值已校准、供应商人民币账单已核对、GraphRAG / Agent 已落地，或把后期计划说成已完成。

开题材料方面：本包有 [`旧开题资料.md`](../旧开题资料.md)、[`中期报告-修订稿.md`](../中期报告-修订稿.md)、[`开题资料与中期报告差异记录.md`](../开题资料与中期报告差异记录.md)；**最初获批开题原件未在仓内找到**。对外应诚实一句「原件未入仓」，**不得把修订稿冒充原始批准文本**。

## 3. 五步业务闭环与三角色

### 3.1 五步闭环（开题「总体目标」的业务表达）

记住一条链：

**课程资料管理 → 授权检索 → 证据问答 → 来源核对 → 教学反馈**

| 环节 | 含义 | 中期能演示 / 能说清什么 |
| --- | --- | --- |
| 资料管理 | 教师或管理员把 PDF 上传并解析入库 | 页级解析与质量门禁；原生 PDF 文字路径（PyMuPDF）；`COVERAGE_INCOMPLETE` 表示**部分页面需核对**，**不等于**整份解析失败（详见亮点④与研究证据 `05`） |
| 授权检索 | 只在用户有权限的课程资料里检索 | 课内成员边界；演示默认 **Dense**（rerank 关） |
| 证据问答 | 有足够证据才生成可核对回答 | 有据回答 / 依据不足 / 系统失败在语义上分开 |
| 来源核对 | 用户回到原文确认 | 引用摘录 + 打开原 PDF，URL 含 `#page=` |
| 教学反馈 | 给教师看提问与依据不足等线索 | 高频问句、依据不足列表等；定位是**教学线索**，不是成绩画像或学情画像 |

讲解时可以指一眼架构总览图，但**少念技术栈清单**；听众更容易记住闭环和角色，而不是一串组件名。

### 3.2 三角色各自卡什么

| 角色 | 中期职责（讲解口径） |
| --- | --- |
| 管理员 | 账号、课程、授权与系统状态可见性（数据库 / 向量模型 / 生成模型等配置态） |
| 教师 | 看资料入库与质量提示、看基础问答反馈；不把反馈页说成完整学情系统 |
| 学生 | 在已加入课程内提问 → 看引用 → 回原页；未加入课程应被拒绝 |

演示账号一般为本地 seed 的 `admin` / `teacher` / `student`；口令不要写进 PPT、讲稿公开段落或录屏。Real 演示需要演示者自备 SiliconFlow（Embedding）与 DeepSeek（生成）Key，只放本机 `.env`，**勿写入仓库或公开材料**。

### 3.3 闭环与核心问题的对应关系

- 「资料管理 + 授权检索」支撑**课界**；
- 「证据问答 + 来源核对」支撑**可核对依据**；
- 「依据不足 / 权限拒绝 / 系统故障」的分流支撑**正确停止与可解释失败**；
- 「教学反馈」是闭环尾巴，中期点到即可，勿夸大。

## 4. 亮点①：课界权限贯穿

### 4.1 是什么

**课界权限**指：用户只能对自己有成员关系（或相应授权）的课程发起检索、生成回答、以及打开该课资料原文。权限不是前端藏按钮而已，而应在检索、生成、打开原文件等路径上被校验。

### 4.2 为什么是亮点

若只做「检索质量」而不做边界，多课系统会立刻变成串课风险：未加入的课仍可能被问到，或同名 PDF 被跨课读到。对高校场景，**拒绝未授权访问**本身就是正确行为，不是产品缺陷。

### 4.3 系统怎么做（讲解层，不展开未公开实现细节）

机制口径可以记为：**成员校验贯穿检索 / 生成 / 打开原文件**。未授权时应表现为无权限 / 403 一类拒绝，而不是「依据不足」或空答装傻。

### 4.4 用什么证据

- 彩排截图：**`10-PERM-无权限.png`**
- 运行卡中的 **PERM** 路径：访问未加入课程的问答页，或临时撤权后再提问（演示后**立刻恢复**成员关系）
- 固定提醒：同名 PDF **不得**跨课串读

### 4.5 边界与禁区（勿夸）

- 只谈**已测 / 已彩排**路径；不要说成「已完成渗透测试 / 完整安全审计」。
- 不要把权限拒绝讲成「模型不会答」；那是授权问题，不是检索或生成质量问题。
- 现场若账号已加入全部四课，需按运行卡说明：口头解释 API 验收，或临时撤权后恢复，避免现场改库失控。

## 5. 亮点②：证据链到原文

### 5.1 是什么

证据链是一条可讲述的路径：

**页级解析与质量态 → 检索（演示默认 Dense，BGE-M3）→ 受限生成与引用（deepseek-flash）→ 用户点引用打开原 PDF（`#page=`）**

它要证明的不是「模型很聪明」，而是「这句话可以指回课内某份资料的某一页附近，供人核对」。

### 5.2 为什么必须强调「检索命中 ≠ 答案正确」

这是全稿最重要的防踩坑句之一：

- 检索可能召回了相关 chunk，但生成仍可能要点不全、偏题、或页码口径不一致；
- 反过来，生成读起来顺，也不等于引用真正支持该结论，更不等于严格命中题集期望页。

因此评测里才拆成「事实要点 / 引用支持 / 严格页命中」等分层指标（见第 7 章），而不是一个「准确率」打天下。

### 5.3 各环各自卡什么

1. **解析与质量态**  
   原生 PDF 走文字抽取；文档可带 `COVERAGE_INCOMPLETE`（部分页空/过稀/异常字符等触发）。它是**需核对信号**，不是「这份 PDF 没入库」。教育学原理 6 份在核实中可无该警告，其它课多数可有警告——说明警告与课程材料形态有关，不能用「有警告=演示必挂」来吓自己，也不能用「能演示=解析完美」来自夸。

2. **检索**  
   中期主演示：**Dense + rerank 关**。Hybrid 等可开关，但 Keyword-only 候选在当前实现下经保守 cosine 门后，**进入最终 evidence 为 0**；因此不得根据小样本差一把分就说 Hybrid 整体显著更好。

3. **生成与引用**  
   生成应受检索证据约束；依据不足时应停止而不是编造。引用区展示摘录与页码等信息，供人判断「支不支持这句话」。

4. **回原文 `#page=`**  
   点引用应在浏览器打开 PDF 并尽量落到对应页。彩排证据用截图 **03**（作答与引用）+ **04**（真浏览器打开 PDF）。讲解时应强调：现场仍优先真浏览器点一次；截图是备份。

### 5.4 证据与演示默认

- 截图 **03**、**04**；可选问答链路图一眼带过。
- Embedding：**BGE-M3**；生成：**deepseek-flash**；检索策略口头固定为 Dense（rerank disabled）。
- 不要临场换模型、不要为了「更好看」当场重入库。

### 5.5 禁区

- 不说「引用存在 = 事实已证明」。
- 不说 OCR / 公式理解 / 图表理解已经完备（公式页可能抽取碎片化，LA-01 仍可能 PASS，二者不矛盾）。
- 不把跨页问答小样本通过率说成「跨页能力专项验证完成」（题集能力边界见 compare 文档）。

## 6. 亮点③：失败语义四分

### 6.1 四种状态分别是什么

| 状态 | 用户应理解成什么 | 典型证据 |
| --- | --- | --- |
| **有据回答** | 课内检索到可用证据，给出带引用的回答 | 如 LA-01；截图 03/04 |
| **依据不足** | 系统判断当前证据不足以支持作答，**正确停止**，不编造 | 如 LA-R；截图 **05** |
| **系统故障** | 后端/依赖异常等，属于「坏了或暂时不可用」，应可重试原问句 | 截图 **11** |
| **权限拒绝** | 用户无权访问该课问答或原文 | 截图 **10** |

口播示范可用 LA-01（有据）对比 LA-R（依据不足），再对照 11 与 10，把四格讲清。

### 6.2 为什么不能混说

混说会直接毁掉产品可信度：

- 把 **依据不足** 说成 **系统坏了** → 学生以为服务不稳定，教师无法区分「该补资料」还是「该找运维」；
- 把 **权限拒绝** 说成 **依据不足** → 掩盖授权错误，也让未授权访问看起来像「模型客气地不会」；
- 把 **有据但点偏** 说成 **完全成功** → 与分层评测矛盾；
- 把 **应答题却 NO_EVIDENCE**（如 PROB-F02）轻描淡写成「拒答很好」→ 掩盖真实限制。

核心口诀：**无证据 ≠ 坏了 ≠ 答案正确 ≠ 无权限**。

### 6.3 明显课外拒答 vs 困难拒答

22 题里拒答子集是 **明显课外**（如 SQL / 框架运维 / 个股建议等）。**5/5 正确拒答只说明明显课外场景**，**不能**外推为「课内相关但资料不足」的困难拒答已经验证完毕。讲解时主动收窄范围，比被评委追问后才退让更稳。

### 6.4 与演示的衔接

主演示建议顺序：先展示有据 + 回原文，再展示依据不足停止，最后用截图或实走区分权限拒绝与系统故障。这样听众先建立「正常路径」，再理解「三种不正常为何不同」。

## 7. 亮点④：可审计分层评测与门禁

### 7.1 规模与质量门禁

- 库：`univ_course_rag_cn_v2`
- 规模：**4 / 27 / 2,501**（课 / PDF / chunks）
- 课程：线性代数、概率论与统计学、人力资源管理、教育学原理
- **`COVERAGE_INCOMPLETE`**：只读核实约 **20/27** 份资料带该警告——含义是「至少一页被标为覆盖异常（空/稀疏/异常字符等）」，**绝不是**「20 份解析失败」。例如仅末页稀疏也可能整份打上警告。教师侧提示应是「部分页面需核对」，**不要编造**库中并未持久化的具体页码列表。

另有一档**弱规则**摘要（非人工正确率）：可答题预期文档/页 **12/12**，拒答 **4/4**。它只能当辅助口径，**不能**代替下面的 22 题开发者核验分层表，更不能叫「准确率」。

### 7.2 22 题是什么性质的证据

- 题集：`研究证据/02-人工核验题集-v1.json`（22 题）
- 实跑对照：`results/manual-verify-2026-10-20-dense.json` / `...-hybrid.json`
- 口径说明：`results/retrieval-compare-2026-10-20.md`
- **verifier=developer** → **开发者核验**，**不是独立评测**，不可外推到全体课程或生产 SLA
- rerank=disabled；禁止把 Token 用量换算成未核对的人民币成本

### 7.3 五个指标：全称、分数、分母含义

**禁止**把五行合成一个「总准确率」。必须原样使用下列全称与分数：

| 指标全称 | Dense | Hybrid | 分母与读法 |
| --- | --- | --- | --- |
| **全部应答题中的事实要点通过率**（即端到端可答题成功率） | **15/17** | **16/17** | 分母是全部应答题（`should_refuse=false`，n=17）。「应回答却未答」（如 PROB-F02）计为失败。因此它比「只看已回答题」更严。 |
| **已回答应答题中的事实要点通过率** | **15/16** | **16/16** | 分母是机器 `status=answered` 的应答题（两侧均为 16）。只评价「已经作答的那些题」要点是否过关。 |
| **已回答应答题中的引用支持通过率** | **16/16** | **16/16** | 同上分母。**引用支持 ≠ 严格页码命中**：摘录可以支持答案，但页码数字仍可能与题集期望不完全一致。 |
| **严格预期页命中** | **12/16** | **12/16** | 同上分母。**不得称为「引用错误率」**。失败常见与页码口径有关：合并 chunk 的 `Chunk.page` 常取 span **末页**，题集 `expected_pages` 按 PDF 阅读器页序标注，二者不一致时会出现「内容在合并块内但页码数字对不上」。 |
| **明显课外问题正确拒答** | **5/5** | **5/5** | 分母是明显课外拒答题。不可泛化为困难拒答能力。 |

机器 totals（辅助理解，勿当成第五套「准确率」）：Dense / Hybrid 均为 answered=16、no_evidence=6、system_error=0；其中 no_evidence=6 = 5 道应拒答 + 1 道应答题 PROB-F02。

### 7.4 如何正确比较 Dense 与 Hybrid

- Hybrid 相对 Dense 在本轮可见变化，主要是排序 / Top-k 组成等（例如个别题事实要点 Dense 未过、Hybrid 过）。
- 候选层会召回 Keyword-only，但 **Keyword-only → 最终 evidence = 0**（保守 cosine 门）。
- **不得宣称 Hybrid 整体显著优于 Dense。**
- Hybrid 历史 JSON 的 embedding_calls / latency 含诊断重复检索开销，**不宜**与 Dense 直接比耗时或调用次数；成本未查账单，禁止估算人民币。

### 7.5 PROB-F02：必须当作真实限制讲

- 问句大意：概率论导论课件目录中，第一章包含哪些主要小节？
